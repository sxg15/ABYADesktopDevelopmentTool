# AI 开发流程：试用准备与验证记录

日期：2026-10-03。对应流程版本：1.1.0。代码、检查、录制验证和便携包构建已完成，现可开始真实任务试用。

## 已完成

- 新建任务区分完整制作/较大改动与局部任务，并可选择允许需求追问或不追问。
- APP 增加制作流程和 Skill 库，显示阶段、待确认文档、反馈、问题、轮次、证据和报告。
- 需求、计划、交付由用户在 APP 确认具体文档版本；CLI 只能提交，不能自行批准。
- 制作状态与历史由数据库保存，导出到任务目录；修改导出 JSON 不会修改批准状态。
- 对并发更新、过期文档、失效证据、未关闭问题、轮次缺失和后四轮问答做后端检查。
- 实际版本从受管实例的启动存档及 Player 文件计算指纹，保存内容改变后需要登记新版本。
- 启用流程后固定安装的 Skill 与题库；普通读取不刷新，升级需要明确操作并保留备份/历史。
- 统一生成需求与方案、开发与迭代、交付与知识分析三类 HTML。
- 增加受管窗口实时录像，随包提供固定版本的 FFmpeg、来源清单和原始许可资料。

本次改动集中在桌面开发工具，未修改 Unity 主程序的玩法、存档或 Runtime API。

## 如何开始第一次任务测试

1. 先退出旧版 ABYA 开发工具，避免两个版本同时使用任务数据库和连接服务。
2. 启动 [本次便携包](<D:/Unity项目/ABYADesktopDevelopmentTool/Publish-Staging-Workflow/ABYA Desktop Development Tool.exe>)。
3. 沿用已有 Player 路径和工作区设置，新建一个任务，选择“完整制作 / 较大改动”和提问模式。
4. 在终端选择 Codex，描述本次玩法和验收要求。建议首个任务规模可控、已有素材可用。
5. 在“制作流程”阅读需求文档并确认；随后阅读执行计划并确认。其余步骤由 AI 在约定范围内推进。
6. 查看问题、轮次和报告；最终亲自试玩并确认交付。确认后 AI 整理收尾，才能标记任务完成。

“确认并继续”会保存决定，并尝试向已打开的本任务终端发送继续提示。若终端尚未打开，
决定仍然保留，打开终端让 AI 读取当前制作状态后继续即可，不需要重复确认。
旧任务不会因打开页面自动变成十二轮任务；需要时在制作页明确启用，原有资料会保留。
当前正常 Publish 目录未覆盖，本次包位于独立的 Publish-Staging-Workflow。

## 使用中的三个注意点

**录像会临时显示游戏窗口。** 不抢焦点，但不要遮挡、最小化或改变录制窗口尺寸；结束恢复原状态。
录像为 15 fps H.264 MP4，目前不录音。音效的实际听感需要单独检查，不能用无声录像代替。

**确认关联具体版本。** 文档修改后需重新提交；存档或 Player 改动后，旧运行证据不能直接当作新版本通过。
更换存档/关卡后，先使用对应配置启动或重载实例，再登记版本，不能拿旧启动目标的指纹作证明。

**检查资料不等于检查体验。** 后端能发现缺项和版本不一致，无法单凭资料证明玩法好玩、画面正确。
还需要 AI 的实际操作、画面审阅，以及你的最终试玩。

## 新 CLI 入口

| 命令 | 用途 |
|---|---|
| production get / update | 读取或按修订号更新任务制作状态 |
| production version | 从受管实例的实际保存文件登记版本 |
| production report | 从数据库生成固定报告和 JSON 导出 |
| skill list / read | 查看当前任务已安装的 Skill 摘要和选定正文 |
| recording tools / start / get / stop | 检查录制组件，录制本任务游戏窗口并取回结果 |

参数以 capabilities 和随任务分发的 production-records.md / recording.md 为准。
没有 production approve 命令；人工确认不交给 AI 填写。

制作资料在任务工作区 artifacts/game-development；运行取证在 artifacts/runtime。
公共知识发布仍是单独审核的动作，本流程只登记采用、候选和工具建议。
