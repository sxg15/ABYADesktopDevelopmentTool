# 行动分栏实现与验证

按用户在设计预览中选择的“行动分栏”方案实现。

## 实现

- 指引位于任务标题之后、对话步骤与页签之前，不在内容滚动区域内。
- 左侧显示状态、操作要求及图标；右侧色块显示处理位置和主按钮。
- 常规字号：标题 24px、操作要求 16px、按钮 15px、辅助说明 14px。
- 等待 AI 使用蓝色和次要按钮；阶段待办为橙色；原生终端交互为紫色；异常为红色；未知/暂停为中性灰。
- 页签标记待回答、待审查及终端待处理数量。另有待办时保留查看入口。
- “查看并审查”直接打开所见文档版本的二级窗口，默认不选择通过，不自动批准。
- 指引不会因轮询抢焦点或反复闪烁；只有新的人工待办短暂强调一次，遵循减少动态效果设置。
- 请求失败清除过期动作；其他任务的状态不能覆盖当前任务。状态不明时不显示“无需操作”。
- 指引按任务内容区实际宽度重排；低窗口压缩次要信息，避免固定阶段导航挡住成果。
- 通知与终端共享剩余高度，不再把高度 100% 的终端推到窗口之外。

## 验证

- `npm run check`：80 项前端测试、42 项工作流检查、12 项 CLI 测试及前端构建通过。
- Rust 格式检查、Clippy（warnings as errors）通过。
- Rust：129 项库测试、2 项 CLI 测试通过；4 项既有真实环境测试默认忽略。
- 新回归覆盖状态配色类别、直接审查、默认不批准、待办计数、失败后清除动作及任务隔离。
- 隔离浏览器使用真实 `TasksView`，从游戏实例页点击引导可直接进入第 2 版文档审查。
- 1280×900 下滚动成果区 321px，指引顶部位置保持 169.5px 不变。
- 853×480 下无页面横向溢出，内容区仍可滚动；低窗口阶段导航不再覆盖成果。
- 等待、终端待处理与阶段待办分别更新提示及页签标记，切换终端入口不创建新会话。
- 截图：`test-evidence/guidance-action-panel-20261012/review-guidance.jpg`。

浏览器检查使用模拟任务与状态，不连接真实 AI，也不代替真实 WebView2/输入法长任务验收。
