## 已实现的行为

- 问答变为“提交并继续”。保存答案后登记继续请求；原回复未结束时排队，结束后重新核对实际状态再执行。
- 同一答案的连续点击不会打断正在执行的模型，也不会多开一轮。未执行的旧答案可以被新的提交版本替换。
- 文档确认和退回通过同一队列继续，仍只由用户批准具体文档版本。
- 暂停取消未发送请求，并中断已启动的执行。重启保留答案、请求和原生身份，不自动启动模型。
- 步骤栏、终端栏和问答反馈读取统一状态。缺少结构化计划时显示模型/任务状态；历史输出有明确标记。
- 新会话尚未开始时显示“待开始”，不会显示“本轮已结束”。下一组问题不会继承上一组的操作提示。
- 构建版本和日期来自程序内嵌信息，并核对清单及 EXE 哈希。相同 Windows 用户和数据目录只允许一个新版 APP。
- 验证包检查通过后替换固定 Publish，保留旧包备份和固定快捷方式。正常 Windows 上下文启动，避免 Codex 打包环境的 AppData 影子库。
- 退出清理改为后台执行一次，避免在界面线程等待 IPC/原生进程清理。
