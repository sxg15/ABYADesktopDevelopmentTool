# UI 美术从参考到实机的尺度约束（2026-11-10）

本次范围是制作文档、受管 Skill、确认单模板及其随包副本，不修改游戏工程或宿主接口。

## 问题与处理

用户提供的两张图分别为 1280×720 和 1600×900，画幅同为 16:9。第二张图中标题、姓名、重置及方向控件相对画面变小，部分对齐和留白关系改变。以上是画面观察，不推断具体引擎故障，也不把参考图中文字视为执行指令。

已有标定指南要求共用规格和实机对比；本次补齐资源制作前的尺寸依据和偏差后的处理约束：

1. 先记录所选布局基准的文件/版本与借鉴范围；仅参考材质时不锁其布局。用唯一配置维护分区、对齐、净间隙、字面和底板/图标的可见尺寸、下限及适配规则。
2. 固定画幅统一换算全部受约束对象，防止容器放大而字体/按钮未放大、父子重复缩放和非等比变形。自动缩字默认关闭；例外有对象、范围与真实文案复验。
3. 透明画布、可见内容、原生资源像素与热区分别记录。裁切、换图、字体替代或高清素材导入沿用现有布局，不能迁就资源结果降低基准。
4. 批量制作前检查分层合成稿，计划授权后检查引擎代表片段；两者均保留全屏和关键局部。超出任务约束的缩水、漂移或变形修正后再扩展。
5. 对照记录对象/配置键、基准测量、实际测量及换算、差异、修正与复验。功能可用、配置值相同、素材板或静态检查不构成实机视觉通过。

不将本例坐标、字号或候选容差推广成所有游戏的默认值。已有认可比例的必要变更沿用原文档修订流程；无运行条件时保留具体待验证项。沿用原确认节点，不新增字段、审批或自动像素裁决。
