# 游戏客户端管理

本分支基于 `origin/dev`，固定管理 `sxg15/PlatverseOutput` 的 GitHub Releases。

## 使用方式

1. 打开左侧“游戏客户端管理”，使用有仓库访问权限的 GitHub 账号的 Token 登录。
2. 可以创建、编辑和删除 Release，上传、删除版本产物；管理操作需要账号及 Token 都具备写入权限。删除会先显示确认，且不删除 Git 标签或已安装的本地副本。
3. 上传完整 Windows Unity 游戏 ZIP，包含游戏 EXE、同名 `_Data` 文件夹与 `UnityPlayer.dll`。可管理其他文件，但只有完整游戏 ZIP 可用于安装；单个文件上限 2 GiB。
4. 在管理页或设置中选版本、ZIP 和本地存储目录，下载并安装。每次安装使用独立文件夹，保留旧版本。
5. 在设置的“目标游戏 EXE”中选择“使用本地 EXE”或“使用远端版本”。远端版本需先安装；如果有多个游戏 EXE，必须明确选择。点击“保存”后生效。

本地模式保留原来的路径选择方式，旧设置会自动迁移到本地模式。更改存储目录只影响后续安装。任务已有的固定游戏版本继续优先使用；此功能不会切换或重启运行中的游戏。

## Token 登录

优先使用[细粒度 Token](https://github.com/settings/personal-access-tokens/new)，只选择目标仓库。读取、下载需要 `Contents: Read`；创建版本、上传和删除需要 `Contents: Read and write`。

如果作为仓库协作者无法选择目标仓库，可使用带 `repo` 权限的 [Classic Token](https://github.com/settings/tokens/new)。Classic Token 的权限范围更广，应设置有效期；GitHub 对细粒度 Token 的协作者限制见[官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。账号的仓库权限与 Token 的授权范围都会限制实际操作。

可以只在本次运行期间登录，或选择在本机记住登录。记住的 Token 使用 Windows 当前用户 DPAPI 加密存储，不放入普通设置、日志、任务上下文、CLI 或导出包。退出登录仅清除本应用保存的凭据，不影响 GitHub CLI 或其他应用。当前未接入浏览器 OAuth 登录。

## 可选更新

已保存远端来源且已登录时，应用启动后和每 30 分钟检查一次更新，也可在设置中手动检查。稳定版不会提示预发布版本；按发布时间判断新版本，同一 Release 的同名产物被替换也会提示。

更新提示只提供查看入口。下载、安装、选择和保存由用户分别操作；检查和下载不会自动修改当前版本。已安装版本可离线使用。若网络断开或 Token 失效，仍保留原来已保存的游戏路径。
