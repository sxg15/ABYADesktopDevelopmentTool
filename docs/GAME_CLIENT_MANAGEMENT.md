# 游戏客户端管理

本分支基于 `origin/dev`，固定管理 `sxg15/PlatverseOutput` 的 GitHub Releases。

## 使用方式

1. 在设置的“GitHub 账号”中点击“使用 GitHub 登录”，在打开的 GitHub 页面输入应用显示的一次性验证码并授权。游戏客户端管理未登录时会显示提示，“前往设置登录”按钮直接定位此区域。
2. 登录后可以创建、编辑和删除 Release，上传、删除版本产物；管理操作需要账号具备仓库写入权限，并允许应用访问该仓库。删除会先显示确认，且不删除 Git 标签或已安装的本地副本。
3. 上传完整 Windows Unity 游戏 ZIP，包含游戏 EXE、同名 `_Data` 文件夹与 `UnityPlayer.dll`。可管理其他文件，但只有完整游戏 ZIP 可用于安装；单个文件上限 2 GiB。
4. 在管理页或设置中选版本、ZIP 和本地存储目录，下载并安装。每次安装使用独立文件夹，保留旧版本。
5. 在设置的“目标游戏 EXE”中选择“使用本地 EXE”或“使用远端版本”。远端版本需先安装；如果有多个游戏 EXE，必须明确选择。点击“保存”后生效。

本地模式保留原来的路径选择方式，旧设置会自动迁移到本地模式。更改存储目录只影响后续安装。任务已有的固定游戏版本继续优先使用；此功能不会切换或重启运行中的游戏。

## 浏览器登录

登录使用注册的 **ABYA Desktop Development Tool** OAuth 应用和 [GitHub Device Flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow)。公开 Client ID 为 `Ov23li0rDQSvLA8yT7sj`，应用不需要、也不包含 Client Secret。请在 OAuth 应用设置中保持 **Enable Device Flow** 开启；开启凭据到期时，应用会自动续期。

私有仓库请求 `repo` 授权，其范围覆盖账号可访问的私有仓库；本应用的业务请求固定在 `sxg15/PlatverseOutput`。浏览器页面由用户完成账号登录与同意授权，应用自动等待结果，不需要手动创建或粘贴访问 Token。验证码过期、拒绝授权或取消后可重新登录；打不开浏览器时可手动访问 [GitHub 设备授权页面](https://github.com/login/device)。

可以只在本次运行期间登录，或选择在本机记住登录。访问及刷新凭据由原生服务管理，使用 Windows 当前用户 DPAPI 加密存储，不放入普通设置、日志、任务上下文、CLI、网页存储或导出包。刷新凭据无效时提示重新授权。退出登录清除本应用保存的凭据并取消当前授权流程，不影响 GitHub CLI 或其他应用；晚到的请求不能恢复登录。旧版已保存登录记录兼容读取，UI 不再提供 Token 输入。

登录、重新授权和退出统一位于设置；客户端管理显示账号状态及账号设置入口。授权成功后远端版本选项自动刷新，游戏来源与选择仍需显式保存才生效。

## 可选更新

已保存远端来源且已登录时，应用启动后和每 30 分钟检查一次更新，也可在设置中手动检查。稳定版不会提示预发布版本；按发布时间判断新版本，同一 Release 的同名产物被替换也会提示。

更新提示只提供查看入口。下载、安装、选择和保存由用户分别操作；检查和下载不会自动修改当前版本。已安装版本可离线使用。若网络断开或登录失效，仍保留原来已保存的游戏路径。
