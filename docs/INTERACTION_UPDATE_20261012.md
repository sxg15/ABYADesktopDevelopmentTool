# 交互引导与美术确认更新

更新日期：2026-10-12。修改位于 ABYADesktopDevelopmentTool 源码工程。

## 需求对应

| 需求 | 实现 |
|---|---|
| 问答增加其他 | 有选项的问题统一提供“其他”，展开必填说明；普通选项和补充说明独立编辑 |
| 输入失焦 | 自动保存不禁用输入，保存快照串行化；轮询不替换正在编辑的内容；弹窗阻止终端抢焦点 |
| 删除冗余操作 | 移除查看全部答案、手动保存草稿、取消问题；保留自动保存状态和失败重试 |
| 提交后关闭 | 答案保存后自动关闭，继续/连接状态由主页面承接；连接失败可重试继续，不重新提交答案 |
| 清晰指引 | 主页面统一显示等待 AI、待回答、待审查、终端待处理及异常状态；终端页共享状态 |
| 无成果禁交互 | 后端 actions 与最终提交检查文件、版本、阶段及反馈对象；草稿、空成果、附件不能解锁反馈 |
| 两级窗口 | 总览只进入审查/反馈；二级窗口阅读后明确选择结论，默认不选择通过；复验关闭也使用二级窗口 |
| 美术确认文档 | 流程 2.1 新增 resources 文档与 APP 确认节点，模板列出风格、资源、约束、图版及验收标准 |
| 点击图片预览 | 图片直接点击或键盘打开；放大、缩小、适应窗口、拖动和前后切换；关闭返回原焦点 |

## 行为边界

- 答案提交不代表批准文档。继续请求沿用原会话和既有幂等队列。
- 审查绑定所见文档修订与哈希；新版本到达后保留意见，但必须重新阅读后才能提交。
- 美术范围为 new-art、reuse-only 或 no-art。后两种仍提交范围与依据，不要求为了流程新画概念图。
- 美术文档绑定当前视觉方案。更新文档或图版后，旧确认不能用于推进后续阶段。
- 视觉反馈会重新打开美术/计划及受影响后续阶段，允许 AI 接收修改请求。
- 视觉复验绑定同一组最新候选图，不要求先有可玩版本；关闭反馈仍由用户完成。
- 旧任务保留固定策略；显式升级保留文档、批准和证据历史，要求补做美术确认及受影响阶段审查，不补造批准。
- 轮询只做可交互条件投影，避免每几秒重算整个 Player 文件指纹；最终作品相关提交仍完整验证。
- 文档正文通过 React 文本节点呈现，不执行报告内 HTML 或脚本。

## 浏览器验证

使用 `npm run dev -- --host 127.0.0.1 --port 1429`，访问 `/scripts/interaction-preview.html`。
此入口只使用隔离测试数据，不连接 Tauri、不创建真实任务或 AI 会话。

- 1280×720：问答“其他”填写、自动保存后焦点保持、提交关闭。
- 美术二级审查：未选择结论时按钮禁用，点击概念图直接放大，返回后意见保留。
- 853×480：相当于 1280×720 的 150% CSS 有效工作区，操作区可见且无横向溢出。
- 800×600：审查区变为上下排列，长内容可滚动，操作区固定可见。
- 测试结束还原浏览器尺寸。截图位于 `docs/test-evidence/interaction-20261012/`。

这属于浏览器实际渲染与隔离交互验证，不等同于 Windows 原生输入法、WebView2 DPI 或真实 AI 长任务的人工验收。
Rust 的四项既有外部依赖测试默认忽略，涉及真实 Codex、Player、沙箱及窗口录像；本次未伪装为已执行。
