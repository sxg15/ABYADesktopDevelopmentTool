# Lua 自主执行重构（2026-10-23）

版本：`autonomous-implementation-20261023`；制作策略：2.4.0。
本次改的是 APP/CLI/随包 Skill，不修改已交付游戏或用户当前任务的批准记录。

## 已实施

- Lua 阶段的问题与整阶段停止解耦。问题严重程度保留，按依赖隔离受影响工作。
- 工作项绑定原 goal ID、需求/计划范围摘要、周期和依赖，定义与执行历史持久化。
- 同一路线无进展最多两次，再换不同路线；耗尽后暂缓，优先执行独立工作。
- 相关构建、实际存档或依赖条件变化后重新评估，改一句摘要或增加无关问题不会重置预算。
- 同一进程内的依赖唤醒重新核对暂停、原生轮次与权限；不清掉用户暂停标志。
  APP 重启仍沿用原子流程的显式恢复，不从旧历史自行启动。
- AI 自测自行闭环，用户反馈保留并集中到试玩复验。收敛与验收通过分别记录。
- 已验证的 PB 等效替代绑定问题指纹、批准范围、版本、周期和证据。原平台问题仍显示，
  但不再仅因它未关闭阻挡本任务；候选差异、过期证据和变化后的问题不豁免。
- production current 返回有界当前上下文；production batch 逐项 CAS 与持久化收据，
  首个失败后停止剩余项，已提交项不重复，不能跨过期间的新用户修改。
- runtime receipt 保存摘要/状态/结果 hash，不保存原始响应或凭据；重复运行 ID 返回
  已完成收据，未知结果不重新派发。同 ID 不同输入明确冲突。
- record-validation-run 将一次真实运行关联到现有自测和美术检查，后端统一登记。
- 新策略保存版本时创建校验后的存档快照；正式试玩再使用独立运行副本。
- 文件级差异清单目前为影子模式；未知 PBArc/PBConf 或 Player 变化仍保守重测，
  不把文件名看似“编辑状态”作为跳过验证的理由。
- 工作队列、当前路线、暂缓原因和交付缺口在工作台可见；保留原有布局和拖动分界线。

## 原生验证发现并修复的问题

1. 测试会话继承了原生只读/人工命令审核设置，停在权限确认。这不是 Lua 或 PB 缺陷。
   增加计划/Lua 阶段的权限提示；APP 不静默改权限。隔离测试明确选择现有 AI 自动审核，
   保持用户真实任务设置不变。
2. AI 登记的 desktopCliReport 进展说明仍为 progress，旧 pending_tools 将它当作真实未结束
   工具，导致工作已完成却不派发下一项。现按来源和类型区分语义记录/Analysis 与真实工具。
   真实命令、MCP 和其他未结束工具仍会阻止危险的迟到重放，不伪造进展说明为完成。

## 验证边界

自动化覆盖：问题隔离、独立工作、路线预算、无关变化、批准范围变化、暂停与唤醒竞态、
部分提交、重复调用、未知结果、凭据不落收据、快照/运行副本隔离、未知差异、验证 run 原子性、
等效替代的版本/问题/证据失效，以及保留交付门槛。

原生验证使用带专用标记的数据目录、合成批准记录、真实 Codex 执行器和两个文本工作项。
平台缺失为明确故障注入；不启动游戏，也不称为“一笔画/大小记忆整项目验收”。
复现实验工具：test-autonomous-native.mjs、seed-autonomous-native.py。

实例复用、能力前置验证和状态触发取证接入随包执行规则，使用现有工具；未发明通用游戏事件
API。3–4 小时是下一轮同规模完整项目的目标，不能由本次合成测试推导已达成或节省百分比。

## 使用与迁移

新任务使用 2.4。旧任务继续固定原策略；需要先暂停其终端，在制作流程的完整资料入口明确
升级，再恢复原任务。升级保留原 ID、成果、问题和批准历史，不自动代批或重启正在试玩的实例。
原生只读/人工逐项审核仍可能要求用户处理命令；可在执行设置主动选择 AI 自动审核。
权限不足、未知写入和用户暂停不能被“自主执行”绕过。
