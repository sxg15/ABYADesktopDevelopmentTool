# 内存保护、包体优化与追溯说明

## 已实施

- 桌面工具按托管实例持续采样私有提交、工作集、系统空闲与提交上限，并关联实例/任务/请求身份。
- 超限创建独立 UUID 事件，恢复后再次超限另建事件。异常退出、中断恢复与内存压力分开描述，不自动认定泄漏。
- 默认限制高开销调用并请求取消。自动停止仅由用户对当前托管实例明确启用；外部实例不可控制，停用不能因日志失败被拒绝。
- 阈值修改及自动停止授权留下操作记录。增长率在至少120个启动样本后启用，绝对内存与系统压力保护一直有效。
- 启动前预留内存，避免多个实例同时占用同一份空闲预算；同实例高开销工具串行，诊断读取保留。
- 调用前流式计算输入哈希、大小和必要参数摘要；日志不可写时阻止新的高开销调用。原始脚本和凭据不复制进报告。
- Codex 上下文采集不阻塞保护，最多读取64个会话目录，从中保留最近三个会话，每会话三轮、每轮32项活动。
- 修正进程监控与 runtime_pid 的锁顺序，避免退出观察持有 child 锁时再请求 live 锁。

包体源代码位于 AbyaPB：架构检查一次同步读取复用一份 UI 页面，避免按每节点/事件重建整页；
页面复制和修订哈希改为流式 UTF-8，保持旧修订结果，并在64 MiB预算及取消边界停止；不跨请求缓存。
同步工具执行片段设置取消上下文，退出即恢复，不跨协程 yield 保留。

## 每个事件的文件

正式数据目录的 `Reports/MemoryIncidents/<事件编号>/` 中保存：

| 文件 | 内容 |
|---|---|
| report.md | 人可读的触发原因、任务/进程、最后样本、操作及 Codex 上下文 |
| incident.json | 身份、启动时间、Player位置、存档、阈值及分类 |
| before-trigger.json | 固定保留的触发前采样及操作，不被滚动数据覆盖 |
| samples.jsonl | 触发后的有界采样；`.previous.jsonl` 为前一个滚动段 |
| operations.jsonl | 请求/会话ID、工具名、输入哈希、必要参数、开始/结束/错误与授权记录 |
| codex-context.json | 过滤后的会话、轮次、活动及采集范围，或明确的不可用原因 |
| outcomes.jsonl / outcome.json | 退出观察、保护停止及失败；请求停止不等于已经退出 |
| player-tail-before.log / player-tail-after.log | 有界、过滤后的 Player 日志摘录；完整日志原位置保留在身份记录中 |

实例详情提供内存、阈值和报告入口；全部报告独立于任务删除保存。重启不自动恢复自动停止授权。
采样可能漏过采样间峰值；这是软件保护，不是操作系统硬内存配额。物理磁盘不可写等失败会显示，
不能承诺在所有系统崩溃条件下保存完整内容。时间相关、历史认可、脚本通过都不是根因证明。

## 复现材料的边界

用户提供的 ZIP 提取到隔离目录，校验1117个清单文件；另一个同内容 Player 目录没有重复提取。
包内是故障后修正保存的存档，不是13:06故障时的完整快照。两个留存 Player 的535个运行文件相同。
不执行包内 apply 脚本，不覆盖原作品。每轮使用新数据目录和存档副本，单实例及有界时间运行。
原始资料、运行回执和样本仅在本机 logs 中保留，不随应用发布或提交第三方素材。

## 已验证及限制

- Unity 2022.3.62f2c1 下14项测试通过，包含旧哈希兼容、范围释放、取消与预算；构建独立诊断 Player 成功。
- 7项内存专项 Rust 测试和3项前端专项测试通过；包含真实进程采样、冷启动、事件恢复及停止结果边界。
- 新诊断 Player 的349节点 UI读取约1.343秒，本轮进程采样峰值3,431,018,496字节，未触发保护。
- 低阈值保护测试中采样峰值3,443,683,328字节；停止后确认进程不存活，并保留请求与 Codex 摘录，敏感测试字段已过滤。
- 初次架构检查约15.557秒返回 manifest.revision 失配；它证明旧清单仍会被拒绝，不是完整校验通过。
- 核对当前存档、关卡和所有清单目标后，仅刷新测试副本的 snapshotRevision；架构快照约16.495秒，清单校验约16.164秒，返回 valid/ready=true、零错误/警告，采样峰值3,401,826,304字节。
- 最终包上的实现一致性检查（implementationLint）约60.016秒，返回 valid/ready=true、零错误/警告；同轮快照和清单检查分别约17.036/17.101秒，采样峰值3,440,914,432字节，未触发保护。耗时仍较高，不能宣称长耗时问题已完全解决。
- 旧 Player及部分冷启动出现 DOTween 初始化异常，分别保留异常退出记录；不能把它们归为同一个内存根因。
- 首个复制脚本在 Node 24.11.1 中异常退出，游戏尚未启动；改用系统复制与测试运行时后继续，未把它记为游戏 OOM。

这些是受控单次结果，不是同源码、同构建设置的严格性能 A/B。原始78 GB峰值的完整归因仍需
故障时存档/堆快照或新的可复现事件。应用保护与诊断 Player 的生效范围必须分别说明。
