# 试玩与反馈卡片整合

用户要求将 Lua 实现、试玩修改阶段的试玩卡片与“补充要求或试玩反馈”卡片合并。

## 实现

在两个阶段的当前工作区，同一个“试玩与反馈”区域依次展示版本、待核对问题、人数与启动操作，以及反馈输入、附件、保存草稿和提交继续。移除成果区中的重复试玩卡片，复用同一 VerificationPackage 组件及原启动接口。

长问题保留数量和全部原文，展开后阅读；默认收起，避免将反馈输入推到大量诊断文本之后。开发成果与执行记录仍可展开查看，历史保持只读。整体沿用现有米色背景、橙色操作和连续滚动。

当前修改版仍使用 currentVersion，Lua 阶段仍使用已验证试玩包；不替换 Player、不修改验收条件，不自动提交反馈或启动 AI。草稿、附件、人数选择、阶段交接确认和运行中禁用规则保持有效。

## 验证记录

- 使用真实 React 组件和见缝插针记录的隔离副本核验两阶段；API 为内存夹具，未触发真实游戏或模型调用。
- 两阶段均只有一处启动按钮；4 窗口请求保留对应版本，切换反馈列表后草稿和人数仍在。
- 长问题可以展开；1280×920、760×720、1080×600 下无横向溢出，反馈和提交可滚动到达。
- AI 执行中仍禁用启动与提交，草稿仍可编辑。
- 已查看宽屏与窄屏运行截图；专项记录见 [界面核验结果](test-evidence/playtest-feedback-20261106/ui-result.json)。夹具验证不代表游戏验收。
