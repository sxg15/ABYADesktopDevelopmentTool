# 制作流程 2.7：阶段边界与 Skill 修复

本次修复把资源/方案阶段的技术问题记录，与当前设计提交条件分开。未解决问题继续保留；材料缺失、问题组、策划反馈和版本批准仍由 APP 校验。

## 已实现的行为

- `stage_contracts.rs` 统一有效阶段门槛。普通 Runtime/manifest 问题不再自行阻止 resources/plan 送审。
- 兼容升级保留原任务、子流程、成果、批准和问题历史；旧设计预检耗尽状态进入历史，不继续提示无效的恢复条件。
- agent 启动游戏和写入工具受后端授权约束。正式实现需要当前有效的需求及计划批准。
- APP 用户可选择已保存的源编辑实例，创建隔离交互小样。副本就绪后才授予 30 分钟授权；范围绑定任务、存档、阶段、周期和需求/计划版本。
- 小样只允许 UI 和事件绑定相关写入，每次核对实际存档路径；不允许切换/新建其他存档或任意 Lua 执行。撤销、到期和范围变化阻止后续派发，在途操作仍按收据对账。
- 普通问题不显示空的“程序问题导出”按钮。静态 `valid/ready` 与工具调用成功、运行验证、人工批准分别记录。
- 任务 Skill 删除设计阶段必须先做实机片段的冲突规则；保留 Impeccable 等能力，按当前对象与阶段加载。
- 固定续接提示缩短为当前阶段、目标、结果及按需参考；维护 Skill 的旧版本细节移入 `docs/skill-history/20261026/`。

## PB 修复

Plastic 变更集 **11806**：

- 完整公开 gameplay manifest 的 components、gameMode、target、bindings 与枚举；scope/authority/logicKind 的 schema 和校验共用常量。
- 错误返回 received、allowedValues、path 和 contractVersion，避免连续猜测枚举。
- 快照提供来自实际 target/eventId 的草稿示例，不伪造对象或运行验收。
- 启动器支持明确指定、未进入全局存档列表的任务副本，核对实际 GUID 和关卡；不会回退到同 GUID 原件。

真实联调发现，旧启动器把工作区副本误报为“存档不存在”。此问题独立于 CLI 连接形式；重试传输不能修复它。
另发现编辑器会重写相同字节的 APA 元数据；小样复制现在核对完整文件集合和实际字节，避免只因时间戳变化误报保存冲突。正式版本指纹规则保持原约束。

| 验证 | 结果 |
|---|---|
| 前端、交互和 Markdown 等回归 | 214 项通过 |
| Skill/模板/资料契约 | 65 项通过 |
| Node CLI/便携包契约 | 31 项通过 |

| 原生 APP 设计送审 | 已通过：无 Player、技术问题仍未解决时可提交美术稿，批准仍等待用户 |
| GPT-6 Astra 规则理解 | 旧 Skill、新 Skill、新 Skill+阶段契约各 3 个场景均通过 |

模型测试是规则理解探针，未执行游戏制作；旧 Skill 本次也答对，不能据此声称修复前必错或证明性能提升。
未以这些测试替代整款游戏的 3–4 小时实测，也未替策划完成设计或作品验收。

## 部署

APP 发布标签为 `stage-contracts-20261026`，任务流程版本 2.7.0。旧任务通过制作流程顶部显式升级；保留原 ID、成果、批准和历史，不自动开始推理。
PB 的新契约和外部副本启动支持需要匹配的新 Player；仅升级 APP 不会改变旧 Player。
诊断 Player 基于当时 PB 工作区构建，验证记录单独标记；无关的现有源码改动未加入本次 Plastic 提交。

## 官方建议对应

[OpenAI：Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)

采用精确触发描述、按需读取、结果导向的完成定义、明确的自主范围和分层参考。后端承担可确定的门槛与授权，Skill 提供判断依据和适用的实践；不依靠重复长提示代替程序约束。
本次只更新项目自有内容及其随包副本，没有覆盖无关的个人/第三方 Skill 或修改用户的模型、权限设置。

原生界面与细项结果见 [验证记录](test-evidence/stage-contracts-20261026/native-app.json) 和 [截图](test-evidence/stage-contracts-20261026/native-design-review.png)。
