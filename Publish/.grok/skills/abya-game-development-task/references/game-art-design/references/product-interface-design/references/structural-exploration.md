# 设计推导与结构方案

用于新产品、完整设计或整体重设计。已有已确认方案的局部实施、局部修复只分析受影响部分，不为数量重做整个产品。
这份方法来自用户提供的[完整提示词](source-prompt.zh-CN.txt)；原文用于追溯设计意图，具体执行仍服从本次用户范围和宿主工作流。

## 编写简短的《设计推导》

合并进已有设计文档，先写具体事实，再写判断；不要变成品牌文案。

| 部分 | 需要回答 |
|---|---|
| 产品核心 | 用户、主任务、最高频动作、第一眼信息、持续信息、可隐藏项、使用时长与不能接受的错误 |
| 平台与环境 | 设备、屏幕/视距、输入、移动或长时间使用、键盘/触摸效率、访问与中断需求 |
| 领域原型 | 完整探索找出至少5个属于该领域的真实工具、媒介、对象、系统或工作流程，不列5个网站凑数 |
| 领域到结构 | 每个原型如何产生信息轴、空间、顺序、层级、操作、定位、视觉锚点或状态表达 |
| 交互模型 | 浏览/搜索/编辑/创建/监控/管理/沟通/控制/分析/内容消费或混合；主循环如何工作 |
| 视觉来源 | 字体、色彩、形状来自什么；内容/媒体承担什么角色；密度与动效为何合适 |

例如“节目表 → 时间成为空间坐标”“剪辑台 → 多轨内容共享时间线”“地图 → 空间位置参与导航”。
“金融 → 高级”“动漫 → 活泼”“AI → 未来”没有产生结构决定，不算推导。
领域原型应有具体关系和适用条件；来源不足就标明假设或范围限制，不伪造调研与观察。

## 比较三个结构不同的方向

完整新设计或整体重设计在正式实现前提出 A/B/C 三个方向，使用相同需求、真实内容和平台约束。
至少在信息架构、导航、空间结构、主内容区域、交互模型、阅读顺序、密度、控制方式中的三个方面明显不同。
用低保真图、交互草图或精简原型表达，不要求三套完成美术资产；不得只用风格形容词代替结构。
三个方向去掉颜色、换成同一字体后仍应明显不同。换色、圆角、玻璃效果、侧栏宽度不能算不同方案。
对每个方向说明主任务如何完成、内容如何组织、平台输入如何影响布局、主要代价和不适用情形。
先用 [结构与默认风格审查](anti-default-audit.md) 检查，再记录保留/淘汰理由；选择最符合产品逻辑的方案，不能默认选择最整洁或最像成熟 SaaS 的一个。
已有明确、确认过的结构或当前请求只是局部变更时，沿用该决定并说明范围；不要强迫用户重新投票。
用户没有参考时，依靠任务、领域关系与平台约束生成方向，不能退回模型最熟悉的模板。

## 留下至少五个产品专属决定

完整设计选定后列出至少5项“产品事实 → 结构/交互决定 → 可观察收益/验证方法”。
决定来自时间轴、空间模型、媒体比例、数据/状态关系、领域编号、专属工作流、信息层级或输入行为。
Logo、品牌色、产品名、装饰插图不计入；常规设置、登录与标准控件不必刻意求异。
每项说明换成无关产品后为什么会失去依据。若五项都是装饰，回到结构层重新推导。
用户已锁定的业务规则、平台、镜头或输入不能为了制造三种方向而擅自改变。

## 已有产品的重设计

现有业务、数据与必要能力是依据；旧 Sidebar、DOM/View 层级、卡片、工具栏或页面顺序不是天然正确的约束。
用户请求整体重设计时，检查是否需要改变信息架构、导航、组件层级和交互模型，并在授权范围内实施。
不能以换色、加阴影、改圆角和字体冒充结构重设计；也不能借重设计破坏业务、丢数据或扩展无关功能。
完成选择并满足宿主已存在的确认条件后实施、查看真实运行结果并复验，不停留在推导或 Moodboard。
