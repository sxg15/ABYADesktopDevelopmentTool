# 审查与对比

先读当前有效要求、禁止项、未关闭反馈、已选方向和真实内容；不只审查上一轮摘要。
记录当前范围、设备/窗口/缩放/镜头/状态、设计与作品版本，以及哪些证据实际看过。

## 顺序与记录

先要求覆盖和任务可用性，再层级/分组、排版、颜色、层次、图像与反馈细节。
顺序是减少返工的方法；遇到已确认根因可直接处理，不为顺序重复做无关工作。

| 位置/对象 | 实际观察与证据 | 对任务的影响 | 判断依据 | 修改与保留项 | 复验结果 |
|---|---|---|---|---|---|

依据可来自要求编号、参考中的具体特征、平台规范、项目规则或可复现操作。
不要求每项必须对应书中编号。将同一根因的多处表现合并，避免列满细碎审美意见。
严重程度依据影响：任务阻断/误导、明显阅读操作困难、局部一致性与润色。
超出本次范围的问题可以记录，不能由严重度标签自动获得重构权限。
区分已观察、代码推断、未验证。未检查的状态不填通过，AI 判断不冒充人工认可。

## 同条件比较

固定有效要求、参考、内容数量、语言、输入、窗口/镜头和状态；方案与实机使用
可比尺度。保留修改前的有效证据，不覆盖已登记媒体或用旧版本代替本轮复验。
检查是否以隐藏说明、减少对象、缩小截图、删掉控制等方式换取整洁。
运行证据绑定当前作品版本；反馈关闭不删除其仍有效的要求。

## 验证本模块的效果

代表样本：有持续引导的桌面工作区；复杂背景与身份色的游戏 HUD；图片及上下文库。
比较要求保留、任务路径、阅读/操作反馈、参考匹配、视觉一致性与实现差异。
可量化的遗漏/裁切/对比度分别记录，审美判断注明观察者与依据，不合成虚假客观总分。
受控界面样本只能证明规则如何应用及组件行为，不能证明 Astra 生成质量提升。
模型对比需同需求/参考/模型配置，保留输入输出与失败结果；单个样本不外推稳定收益。
没有真实模型试用或策划评价时明确留空，不生成测试结果或满意记录。

局部修复复验受影响范围；完整设计按原 Skill 要求检查代表流程。无证据的风格
替换或过度留白应撤回，再回到当前任务依据。
