# 平台与游戏适配

以支持的平台和项目规范为准，不默认将 375px 手机视口加入桌面工具验收。

## 桌面工作区

先列用户持续可见的信息和高频路径，保留已验证有效的导航、流程节点、任务说明、
快捷操作和错误恢复。多面板允许局部主操作；选中状态不等于执行状态。
按实际支持的最小窗口与常用窗口检查，Windows 项目覆盖 100%/125%/150% 缩放中
实际支持的组合。浏览器视口模拟只能证明布局，系统 DPI 与原生焦点需原生验证。
检查长中文、英文混排、数字、字体回退、滚动边界、弹窗、键盘焦点及输入法。
终端保持高密度、语法色、选择复制和历史位置；美化不能改变输入或会话生命周期。

## 游戏界面

先明确镜头、战斗/探索/建造等核心状态、输入与视距。HUD 主信息不能被世界效果
遮挡，反馈强度应匹配玩法优先级，不能为了“统一色彩”合并敌我或资源身份。
在明亮、黑暗和高细节背景上检查；透明叠层按合成后背景判断。一个纯色色对通过
不能证明动态图像上的文字可读。必要时选用局部底板、描边、遮罩或空间避让。
保留既定的像素、漫画、硬边、拟物或其他风格。字体、图标和 UI 材质与世界共享
有依据的视觉语言，不将所有游戏改为浅色工具界面。
用真实剩余物品、最低/最高数值、多人身份与异常状态检查。不得以数字标签代替
策划明确要求的实物表达，也不能用减少对象数量让截图显得整齐。
按支持的分辨率/宽高比、安全区域、手柄焦点、触摸热区验证；不擅自增加平台。
场景构图、角色造型、骨骼、动画和特效制作仍使用游戏美术专项规则。

## 反馈与时间

确认点击/按键被接收、任务正在处理、真实完成和失败恢复之间的差别。
动画时长由响应节奏、玩法和平台决定；支持减少动态效果时使用对应设置。
静态截图不能验证操作时延、遮挡时序、输入焦点、打断或连续动作，需实际操作或视频。
