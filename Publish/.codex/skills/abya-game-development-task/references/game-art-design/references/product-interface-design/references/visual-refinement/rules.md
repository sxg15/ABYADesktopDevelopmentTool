# 规则与适用条件

硬要求来自当前任务、明确禁止项、实际平台能力及适用规范；下表是诊断建议。
每次只处理有证据的问题，不把例子改成跨项目禁令。

| 观察 | 方法 | 例外及验证 |
|---|---|---|
| 用户找不到当前任务或下一步 | 综合字重、位置、色彩与空间建立阅读顺序，适当减弱竞争元素 | 持续监控的信息仍需可见；不能删去引导栏、任务说明或必要控制来突出按钮 |
| 每个操作都在争夺注意力 | 按当前任务/操作区域分配主次，主操作与对象选择、危险状态分开表达 | 多面板工作站可有多个局部主操作；不要全 APP 只留一个可见按钮 |
| 分组难辨 | 相关项目靠近，组间距离大于组内；必要时使用边界或底色 | 表格、终端、清单可保持高密度；用查找/比较任务验证，不统一加大留白 |
| 尺寸不协调 | 复用现有间距、字号、圆角和密度变量，为确有用途的例外命名 | 字形光学校正、细边线不必强凑比例；不要求相邻刻度至少差 25% |
| 色彩割裂 | 为背景、文字、动作、选择、状态和对象身份定义语义色；检查实际色对 | 文字层级可简洁，但阵营色、品质色、语法高亮不计入固定三色配额 |
| 彩色区域文字发灰或刺眼 | 在实际背景上调整亮度、色相关系与字重，检查对比度 | 灰字、透明白字不天然错误；先计算合成色并看实际渲染，不机械换成同色文字 |
| 层次与交互不一致 | 边界、表面亮度、遮挡与阴影共同表达空间和状态 | 不固定阴影级数或光源方向；漫画硬阴影、平面风格、暗色工具采用自身规则 |
| 字体看着整齐但难读 | 检查实际语言、字重、基线、行距、数字与回退字体 | 不把英文 45–75 字符直接套给中文、代码、HUD 或短标签 |
| 图片和图标不协调 | 在最终显示尺寸比较笔画、光照、细节密度与视觉重量 | 图标不一定比文字更淡；美术参考完整查看，不能为卡片整齐而裁掉关键内容 |
| 看不出是否已响应 | 设计实际可达的悬停、焦点、按下、选择、忙碌、完成、失败与恢复 | 没有的状态不造功能；反馈对应真实结果，不能用动画伪装完成 |
| 空白或异常页面使用户无从继续 | 说明当前情况并提供有用下一步 | 空状态是否阻断取决于任务影响，不能全部机械定为最高严重度 |
| 布局有明显通用模板感 | 核对每个容器、装饰、按钮和图标的任务用途；恢复对象间真实关系 | 卡片、渐变、大圆角、标准控件均非禁用；有品牌/玩法依据就保留 |

色阶、留白与字体规范应先与现有项目对齐。现有系统不足时逐项补足，不能仅为
采用本模块新增框架、迁移组件库、生成另一套主题或覆盖项目约束。
