# UI 设计交接：沿用现有美术节点

下文 resources、direction、artDesign 是 ABYA 的宿主映射示例；其他项目使用既有设计文档与等价字段，不要求安装 ABYA 或新增状态机。

在已选方向进入资产制作、实现、精确还原或局部视觉修复时读取。以下内容补入既有 resources、direction 与任务内 DESIGN.md，不另立 UI 审批单，不直接改任务导出 JSON 推进状态。

## 1. 约束与记录位置

先对照当前 artDesign.sources、有效 requirements、反馈和确认版本；保留 requirementId、sourceId 与原句。图像解读标为推断。保护项写明版本、具体对象/区域和本次可改范围，不能以“统一视觉”覆盖已认可设计。

| 内容 | 既有记录位置 |
|---|---|
| 玩家决定、信息顺序、动作流程、为何这样分区 | direction.tasksAndInformation |
| 平台、视口、镜头、输入、安全区与遮挡 | direction.platformAndCamera |
| 字体样字、身份/状态/动作语义、密度与层级 | direction.visualRules |
| 代表片段、需要验证的状态/分辨率/输入组合 | direction.representativeScene / acceptance |
| 唯一配置、组件/图层、资产规格、来源与保护项 | direction.assetProduction |
| 当前组件能力、真实字体可用性、限制与替代 | direction.feasibility |
| 实际参考检索结果及使用取舍 | direction.librarySearch 与既有参考分析 |
| 要求落点、实现对照、证据与剩余差异 | 现有 coverage / realizations / visual observations |

宿主接口字段以当前 schema 为准；表中是设计内容的归属，不是新增 production 操作。DESIGN.md 与规格文件按宿主既有 register-artifact 方式登记，在 resources 引用当前版本。

## 2. 唯一配置与真实字体

优先复用实现已经读取的配置；尚无配置时，按现有工程约定建立一份任务内 UI 数值 JSON。注明路径、版本/摘要、单位、坐标原点、参考视口及实现读取位置。DESIGN.md 用配置键引用规则，避免文档、组件与另一份 JSON 各有一套常量。
按组件实际需要表达布局约束、锚点、边界、间距、文字尺度、层级、颜色语义与状态参数；不要先设计无法消费的大型通用 schema。跨分辨率用约束/密度模式，不能只缩放整屏。
字体证据至少包含实际文件或引擎字体资源、字重/回退和本次样字。样字取真实中文、拉丁字符、数字、符号与长名称；如“生命 128/240”“巨型机械守卫”“READY 00:08”。样例按游戏内容替换，不要求每个游戏都显示这些字段。
在最终引擎/平台与显示大小查看字面高度、笔画、字距、基线和多位数字稳定性。生成概念字形与某字体名字相似不证明能够还原；字体授权与缺字情况未核实就注明未验证。
尺寸标定以任务已约定的对象、测量方式和容差为准。没有约定时写候选与影响，不设置全游戏统一像素容差或虚构还原率。

## 3. 控件必须可以操作

为受影响控件保留一份紧凑状态/动作表，可直接放 DESIGN.md 的 UI 章节；局部修复只列受影响行。不要把以下列头机械扩成每个界面的全部状态。

| 对象 | 输入/触发 | 动作与数据变化 | 可达状态及反馈 | 焦点/取消/返回 | 配置键、资产层与证据 |
|---|---|---|---|---|---|
| 当前组件的稳定名称 | 点按/按键/导航/事件 | 实际调用意图与条件 | 与玩法相符的状态 | 去向及保留上下文 | 可定位到当前版本 |

区分默认、hover、焦点、按下、选中、禁用、冷却和锁定等实际语义；例如“锁定关卡”须能解释解锁条件，“禁用按钮”须有原因。需要加载、失败、空态时才补对应恢复，不凭模板造功能。
触摸的提示与关键动作不能只能悬停出现；手柄焦点应有形状/边界等稳定标记，导航顺序与空间关系相符，弹层关闭后恢复合理位置。鼠标悬停、键盘/手柄焦点和持久选择分别表达。
动作响应与表现动画分开：使用/装备/重试先及时反馈，装饰按需播放；重复按键、切屏、取消、跳过和动画中断后状态保持一致。实际有风险的动作才用确认，不给高频操作普遍加弹窗。

## 4. 资产与图层

文字、动态值、图标、装饰背景、控件底板、交互热区、选中/焦点和状态覆盖分别可控制。控件尺寸变化时说明九宫格/切片或其他伸缩方式、不可拉伸部分、透明边距与内容区。
资产清单沿用现有资源确认单：稳定名、用途、来源/许可状态、尺寸与最终显示大小、格式/透明/切片、支持状态、复用对象、加载和性能约束。已有资产优先核对实际可用性，不为交接制造新增资产。
身份色与状态色分别映射对象；同一红色若同时表示敌方、危险和可点击，应根据本游戏上下文解决歧义。必要时增加形状/图标/文字，不擅自把阵营色替换为主题色。
HUD 在实际角色、目标、弹道、场景亮暗和高密度反馈下检查；跟随标记、世界空间 UI 与屏幕 UI 明确遮挡、缩放和层级规则。风格化纹理不能吞掉数字、焦点或操作反馈。

## 5. 从代表片段到实机证据

先选一段能暴露当前风险的真实流程，例如“手柄背包比较并装备后返回”或“触摸战斗中技能冷却结束”。方案图、标定片段与本版实机使用可比较的内容、视口、镜头和状态；内容不一致时明确限制。
静态截图检查真实字形/大小、边界/净间隙、密度、层级和遮挡；实际操作或视频检查输入、焦点、时序、重复触发与打断。编译、坐标数值或 JSON 校验通过不能代替查看画面。
按风险补最长名称、最大数值、满容量、分支解锁、输入切换和支持的视口；只列本次适用的组合。问题按“对象/证据 → 观察 → 玩家影响 → 要求或设计依据 → 修正/保留 → 复验”记录。
证据绑定当前实现版本、相关要求与受影响组件；未完成的关键状态、缺少设备或无运行能力分别注明，不补造通过。不要用候选参考图、模拟截图或旧版本实拍证明当前实现。
功能可用、视觉质量、方案还原、人工认可分别记录；历史案例认可与 AI 自检不可填成本任务的策划验收。没有实机证据时交付设计与具体待验证项，不宣布视觉验证完成。
