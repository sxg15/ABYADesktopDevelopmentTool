# 飞书同步与ABYA交接

## 目标与边界

用户已授权后续玩法文档直接同步飞书，无需逐次询问。读取可用飞书文档技能，优先已授权的用户身份和CLI/连接器；能力不足再用浏览器。不要扩大权限、发送通知或覆盖无关内容。

- 指定交付目标时遵循目标；仅供参考的原文不自动成为覆盖目标。
- 一个玩法维护一个固定飞书交付文档。修订先读远端最新正文、图片/附件与版本，合并用户修改，原位更新正文与输入包；版本升级不另建文档，也不把参考原稿当成新的交付副本。
- 未给目标链接时，先查已知交付记录或维护表确定该玩法的原文档；无法确定则询问目标，不自动新建。确为首次交付且没有现有文档时，也需用户明确同意新建后再创建；查找期间可先完成本地稿。
- 本技能只提交设计输入；后续制作技能深化资源、实现与实机验收。遵循目标任务固定policy，不伪造approved/accepted或模板选择，不另建制作流程。

## 同步步骤与完成条件

1. 从同一份定稿生成在线正文和UTF-8 Markdown包，版本一致；图片按[图片索引](ui-reference-guide.md)选取、上传并附用途图注，不能用本机路径冒充在线图片。
2. 原位更新已确定的目标；仅在满足上文首次创建条件时新建。附同版ZIP，替换旧包与过时参考，保留无关资源。同步返回不确定时先检查远端，再决定重试，避免重复。
3. 回读标题、版本、关键规则/数值、受影响章节、实际图片块和附件；校验ZIP中文件齐全、每项必需媒体均有Markdown引用、引用能解析且与线上媒体一一对应。正文文字、代码和表格须与远端一致，不能只比标题或附件哈希。
4. 记录目标URL/标识和版本供续改；返回飞书链接及输入包。认证/权限/上传失败时保留本地成果，准确报告未同步范围与需要的操作，不宣称完成。

仅维护Skill时不自动重写历史飞书文档；用户要求迁移某份文档时才走上述同步。

## 输入包

格式快照核对于2026-11-03：ABYA工作台接受md/txt/docx/zip及常见图片。Markdown ZIP须有.md，成员仅用md/txt/png/jpg/jpeg/gif/webp；不要依赖JSON/HTML/脚本/SVG被导入。附件及解压总内容分别≤32 MiB，≤256项，单张参考图≤16 MiB。

最小结构：gameplay.md＋reference/图片；来源并入正文，有独立需要才加references.md。Markdown使用包内相对路径；避免绝对路径、越界、符号链接和大小写重名。只放当前方案及所需参考，不放旧稿、Skill、脚本或多套候选。图文必须一起交接，优先完整ZIP。技术附录单列时在主文链接，图片使用明确图号/效果ID及用途，不只列文件夹。

### 可复用导出与媒体检查

使用[export_document.py](../scripts/export_document.py)把定稿XML或CLI完整fetch JSON导出为Markdown。传入资源目录及附录标题时自动分拆，保留图片、表格、链接和代码；无法识别的块报错，不静默丢弃。导出后检查每个XML图片都映射到唯一包内文件、正文/附录有对应图片引用、资源目录没有未引用媒体，再压缩。相对链接检查必须同时验证“应有的引用存在”，空引用集合不算通过。

调用示例：`python scripts/export_document.py --input draft.xml --package package --appendix-title "附录｜特效实现资料"`。验证远端时将最新fetch JSON作为输入，输出到单独目录（`--output-dir remote-render`），再逐份比较生成的Markdown；不覆盖本地定稿来制造一致。ZIP另检查解压成员与同版资源哈希。原始XML按元素标签识别，不把资源的name属性误当标签。

保留用户对规则和美术参考的明确认可；这种设计认可不等于制作工具的审批状态或实机验收。R15按用户要求直接复用，其他参考按其职责转化为运行资产，不因导入而自动标记制作完成。

## 特效库交接

后续文档从[abya-crayon-paper-effects](../../abya-crayon-paper-effects/SKILL.md)读取所用版本、effects.json、manifest.json、接入/运动/验收规范及所选效果GIF。库缺失或资源不全时说明具体缺项并定位原库，不悄悄改为自主设计。

- 正文写库名/版本、效果ID及本玩法适配；ZIP附必要的源透明PNG与GIF运动基准，保留原文件SHA-256并标为来源参考；平面运行素材若已制作则另附、另记摘要和源ID映射，未制作明确列为资源任务。材质覆盖范围遵循[F1](button-system.md#特效材质适配)，不得把源素材冒充平面成品。GIF只作比对，不能直接播放为游戏特效，也不带入示例数字、按钮或背景。
- 为保持上文导入格式兼容，把所用效果配置（包括粒子初值、素材映射）、相关manifest条目和必要运动公式放入`effects-reference.md`，JSON可作为Markdown代码块完整保留，不依赖独立.json或.py被导入。附源库相对路径、素材摘要和采样代码来源；允许接手工具按公式实现引擎适配，外观仅按F1做限定平面适配，运动不得另设计。
- 主文链接该文件及素材，形成自包含输入包；在线文档先给效果触发摘要，完整配置/公式/摘要和GIF/透明素材集中在文末技术附录，附录内容与包内同版。无法在线预览的源参考及已制作的适配素材仍须在ZIP内。已存在库的工程也核对版本和素材摘要，不假定另一agent已安装。
- F1负责玩法时序，库负责视觉参数；正文明确纸片余韵不延长锁定、普通切题不清尾部、page-turn是否采用及相对基准的适配。所选GIF不是多套候选，不受“输入包不放多套候选”限制。

## 何时核对开发工具

正常文档修订不扫描仓库。仅在接入方式、导入版本或制作边界发生变化时按需读目标仓库：
- .codex/skills/abya-game-development-task/SKILL.md及受影响的production-stages/requirements模板。
- 美术边界看其game-art-design/game-ui-design相关约束；精修不能改玩法或已确定的系列样式。
- 导入行为看src-tauri/src/modules/tasks/production/workbench_import.rs及src/features/tasks/ProductionWorkbench.tsx。

上述路径是定位入口，不代表平台当前能力已验证。无法核对时仍提供普通Markdown包，并说明版本未核对；不编造API、任务状态或流程豁免。
