# 平台与输入适配

只采用目标产品涉及的部分。熟悉的平台习惯是基础；不以制造差异为由破坏可预期行为。

| 环境 | 优先验证 |
|---|---|
| 桌面专业工具/编辑器 | 长时间操作的信息密度、窗口缩放、稳定工作区、键盘路径、焦点、批量操作、对象选择和上下文操作；只为真实需求添加快捷键 |
| 移动/触摸 | 单手触达、可点击区域、滚动与手势冲突、软键盘遮挡、安全区、返回和中断恢复；不能依赖 hover 才发现功能 |
| 平板/手写笔 | 画布与工具的关系、笔和触摸分工、横竖屏、双手使用；不把手机界面简单放大 |
| 电视/遥控器/Kiosk | 从真实视距读文字、焦点导航顺序、可预测返回、超时与共享设备数据清理；不依赖精确光标 |
| 游戏 HUD/游戏菜单 | 游戏过程中的注意力预算、输入设备、遮挡玩法、身份/队伍/状态色的区分、暂停和结算层级；玩家信息不可借错误视觉暗示泄漏 |
| Web 内容与工作应用 | 阅读或工作任务决定布局；验证响应式、浏览器缩放、键盘语义、链接及历史行为，不把所有页面当营销落地页 |

## 游戏界面的补充判断

HUD 先保护玩法视野、即时信息和输入响应；菜单/物品栏按真实任务组织，不因为参考是网页卡片就沿用其结构。区分镜头内世界对象、世界空间 UI 与屏幕 UI 的缩放/遮挡，纸层阴影不能误导道路、障碍或可交互性。
手柄选中、键盘焦点、鼠标悬停与触摸按下分别设计；只覆盖当前目标输入。身份/队伍色和危险/选中/成功等状态色分别定义，关键状态有颜色之外的提示。装饰动画可取消或替换，不阻塞玩法判定与连续输入。
网页风格规范及示范只提供候选方法；实际中文/数字字形、原生控件、输入和运行证据仍需验证。缺少运行能力时记录具体限制。

## 共同检查

- 焦点、悬停、按下和选中是不同状态；触摸环境提供不依赖悬停的必要信息。
- 高风险低频操作的位置、文案和恢复方式应与高频操作区分；沿用已有确认机制，避免新增无意义弹窗。
- 清楚指定哪个区域滚动，哪些信息固定；固定工具条不能吞掉小窗口的主工作区域。
- 在实际目标窗口、显示缩放和内容语言下检查，不用单一设计稿宽度代替平台验证。
- 颜色和动画之外提供状态信号；尊重平台字体缩放、减少动态效果和可访问输入需求。
- 约束存在冲突时记录取舍，例如更多内容同时可见与触摸可操作性，不宣称一种尺寸适用所有设备。
