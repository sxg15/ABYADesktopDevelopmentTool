# 游玩界面 UI 与键位布局

本文件是现行UI几何与组件规格的唯一来源。2026-11-12用户要求以上UI全部尺寸和位置严格还原、文档写明；以下数值取当前布局稿，并合并后续无按钮规则，作为当前实施基线。只在用户明确微调后更新，不能由生成文档自行近似或重新设计。该基线不代表已做实机验证。

仅适用于游玩界面；准备、结算等内部布局与皮肤不受本条约束，全流程键盘与白圈规则仍有效。参考图只承担指定职责；[v0.5布局图](../assets/ui-layout-20261112/layout-review-v05.png)和[HTML](../assets/ui-layout-20261112/layout-review-v05.html)仅保留历史外观，其0.6px描边、左上对齐按下图、按下图标中心上移及旧“待微调”注释均已失效，不作为实施代码。现行描边和两态底对齐以本文件及[局部核对页](../assets/ui-layout-20261112/state-corrections.html)为准。图中测量线、占位九宫格、“游玩区”、调整说明与底部状态样例不是运行UI。

## 坐标与固定外框

每局开始前的321使用[开局倒计时固定规格](start-countdown.md)，其中心/三张固定矩形独立于本文件的按钮B、可用区A和游玩主体G；不得把倒计时按当前游戏盘面重新居中。

基准视口1600×900，左上原点，矩形统一写`(x,y,w,h)`，单位为UI像素，包含描边。不得将左侧大区域P与游玩主体G混为一谈。

| 元素 | 基准矩形 |
|---|---|
| 固定背景BG-01 | (0,0,1600,900)，原图覆盖且水平居中贴底 |
| 左侧大区域P | (5,5,1192,890) |
| 右侧比分区域Q | (1197,5,398,890) |

任意视口W×H：`N=W−10; M=H−10; R=floor(0.25N+0.5); L=N−R`；P=(5,5,L,M)，Q=(5+L,5,R,M)。右侧占净宽25%，左侧75%，两栏相接不留中缝。四周5px为最终UI像素，不随内部缩放，露出R15原图；底衬补齐圆角缺口，外框阴影不得覆盖露底。背景覆盖公式和主题见[系列视觉](series-visual.md#固定大背景-bg-01)。

## 按钮类型与键位

| 动作 | 形状／提示 | 输入及位置 |
|---|---|---|
| 方向移动 | 方形；W、A、S、D | W/↑上，A/←左，S/↓下，D/→右；W在上、ASD在下的倒T形，始终最底部 |
| 重置本题 | 圆形；R | 横向U形开口朝左，右弧连接上下两臂，左上端箭头朝左；放方向组上方并靠左 |
| 选项 | 长方形；1、2、3、4…… | 视觉上到下依次编号；在已有组上方向上扩展，编号不倒序 |
| 特殊动作 | 逐项定义 | 每次文档交付后告知用户，直至明确审批；不能因旧稿已有就认为通过 |

全部操作按钮位于左侧按钮区，仅按真实动作出现；由底向上装配方向→重置→选项。选项与方向允许并存，v0.5无选项仅是当次预览。缺少某组时撤掉该组及其空位。用户明确保留的盘面手势另按玩法契约处理，不凭空增加操作按钮；局外输入见[键盘规范](button-system.md#全流程键盘与白圈提示)。

特殊按钮告知必须列动作、原因、形状／图标、真实键位、尺寸、位置、两态和审批状态；记录用户原话、日期及依据。语义／键位／形状实质变化重新告知。超过可用数字单键的选项按特殊映射处理，不把“10”画成可单次输入的键名。

## 几何与等距

B是全部实际按钮槽、白圈、描边及预留状态的并集；槽作为状态稳定的保守边界，不能按下后收缩。B.left−P.left=P.bottom−B.bottom=m，不能漏算白圈的左10、上16外扩。各组靠左，以可见边界间距g向上堆放；只计算实际存在的组。

有按钮时：`A.left=B.right+g; A.right=P.right−m; A.top=H+g; A.bottom=P.bottom−m`。

**没有按钮时，按钮区不存在：B=null，不渲染／预留按钮列、占位容器或按钮到主体的额外间距。** 此时`A.left=P.left+m; A.right=P.right−m`，上下边界仍为`H+g`与`P.bottom−m`。因此A和游玩主体G的水平中心均为P的水平中心，不能保留有按钮版本的偏右位置。

G为实际盘面／主体整体可见包围盒，不强制巨大卡片。`G.x=A.x+(A.w−G.w)/2; G.y=A.y+(A.h−G.h)/2`。左右净空相等、上下净空相等，两个方向的净空数值可不同；像素取整差≤1px。玩法专属G尺寸须在文档明确，不能只写“居中／适中”；上下每侧预留至少max(48s, A.h×8%)作为设计校验下限，空间不足先调整玩法主体，不能私改固定UI。

2026-11-12用户指出连线加法盘面太小，并要求“后续的游玩区域都调大一些”。在不改变上述固定UI/最小留白的前提下，各玩法将真实盘面或物件整体放大到合理可用范围，不仅放大空容器；栅格/主体优先使限制轴接近可用范围上限（例如高度约80–84% A.h，若宽度先受限则按原比例）。保留数字、负号、特殊格和物件可读性，不用空白巨大题卡伪装放大；每份图文写明新的实际G与净空。该偏好不允许缩小固定按钮、顶部UI或挪动75:25外框。

## 其他视口适配

内部统一尺度`s=min((W−10)/1590,(H−10)/890)`；固定槽、字体、图标、描边、白圈、内边距和组间距均乘s，四周5px例外。外框按75:25重算，不将整屏缩小居中产生额外露底。

- 顶部以P锚定：秒表左上=P+(24s,24s)；底框=P+(36s,37s)；数字=P+(103s,37s)。尺寸按表乘s，H=P.top+112s。
- 轮数框右边=P.right−24s，上边=P.top+31s，宽194s、高74s。教学左边=P.left+256s，上边=P.top+24s，高88s；右边=轮数框左边−24s。教学宽度由左右锚点推导，不独立拉伸字号／边角。
- 按钮B以m=40s贴P左下，组间g=24s；所有实际组重新装配。G在重新计算的A居中，无按钮分支仍取完整P的水平中心。
- 右侧比分标题偏移Q+(32s,34s)；列表偏移Q+(27s,132s)，宽Q.w−54s，其他行内尺寸统一乘s。

文档写明支持分辨率与最小尺寸，逐一检查容纳、文本和命中≥44×44最终UI像素。若不能容纳，不临时单独缩按钮或字体；明确超界项及所需调整，由用户微调规范。不得把未经检查的所有宽高比声称已支持。

## 右侧比分内部基线

采用当前布局稿：标题“本局得分”起点(1229,39)，28px/800；列表(1224,137,344,高度按席位数)，行高110、行间16、内边距20、行内gap17；头像54×54含3px边，名字24px，分数40px/700。行内垂直居中，分数靠右，名称可省略但身份仍可识别。圆角18、2px暖褐边，浅奶油面；主题颜色见系列视觉。1–4个实际席位，本人第一并标“你”，对手固定席位顺序，结算才排序。少人不缩右栏、不补假人／空卡。

## 文档维护与核验

每份开发文档按[必填UI规格](writing-guide.md#ui规格必须在文档展开)自包含列出当前数值、适配公式、实际G尺寸和有／无按钮分支，不能只附图或写“按Skill”。固定参数、公式推导、玩法专属设计初值分列；历史版本不进入当前实施表。

具体玩法按钮维护须展示该玩法更新后的局内布局图并记录版本／展示依据，补两态对照；核验输入、字体、实际轮数语义、等距、无空列和特殊按钮审批。图文包同版且回读后才登记已应用。仅维护本规范不自动迁移旧稿，不等于运行验证通过。

本次两项防回归检查随新稿、相关修订及实现交接执行：

- 最终显示尺寸核对倒计时20/10/9/0及轮数1/10，两者必须可见完整连续描边；同时看100%原尺寸和局部放大，不凭配置中有outline字段判通过。检查实际支持的最小视口（本次问题截图约900×500的游戏内容区可作为缩小对照），不将未支持的分辨率冒称通过。
- 同一按钮、槽位和视口对照常态→按下→松开/取消：三种皮肤底边坐标分别不变；所有方向图标、重置符号、选项字的按下中心y大于常态，尺寸不变；白圈及命中框不动。键盘和指针都触发检查，不能只交常态图。
- 文档/示意图检查与运行检查分开记证据。制作端须提供当前运行版文字近景和两态截图/视频及中心/底边坐标；未得到运行证据时列未验证，不写“不会再出现”或“实机通过”。
