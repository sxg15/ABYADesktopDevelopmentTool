# 文档结构与检查

本文件只规定成稿内容与检查范围；具体参数来自规则设计、多人、交互反馈、UI布局和系列视觉，不在这里另建规格。局部修订保留有效章节与稳定REQ编号，仅复核变更及其依赖。

## 成稿结构

成稿前先按[设计前局内图](ui-reference-guide.md#设计前局内图)制作并展示当前玩法效果图；采用的V图在美术/UI节就近呈现并随包交付，不能仅附通用主题参考。

标题和简短版本信息之后，先给人能读懂的规则概述：默认3–4句、约80–150字，说明做什么、按什么、如何继续、多久及怎样赢，以及人数和添加Bot入口。错误扣分或解谜重试须简述；不放状态机、网络术语和美术参数。最终回查概述与细则一致，不能把“最高分”一概改写成“答对最多”。

| 章节 | 必需内容 |
|---|---|
| 1. 规则概述 | 按上文描述玩家体验。 |
| 2. 玩法参考与本版改动 | 原链接、关键片段和G图就近呈现；区分可见机制、自主设计与PC按钮映射，图片输入不编造视频。证据要求见[图片索引](ui-reference-guide.md)。 |
| 3. 核心规则与参数 | 初始状态→操作→判定→反馈→新题/本题重试→截止；计分及同分、三档参数、持续供题/去重/有解性、各档耗时与整局机会估算。连续动作明确挑战单位和失败恢复点。 |
| 4. 按钮操作与反馈 | 按钮文案、归属、权限、启用条件、动作结果；列出覆盖所有页面与弹窗的键盘映射，确保可只用键盘完成，并定义每个按钮左上白圈提示、焦点、冲突与跨页按键清理；集中定义按钮提交/取消、F1窗口、效果触发与清理；明确翻页采用与否。按钮视觉参数与特效空间映射放第6节，库内公式放技术附录。 |
| 5. 多人、Bot与开局结算 | 准备→选难度/增删Bot→准备/开始→对局→结算/重开；席位/权限、公共和个人状态、同步与截止、加入/离开/断线、排名。给普通Bot各档H、D范围及失误模型；入口坐标引用第6节，不在此再定义。 |
| 6. 美术与UI | 固定R15＋选定BG-A–BG-D之一；附对应R22–R25并写职责。给布局、HUD/时钟/按钮规格、底板与操作面明暗层级、底纹、边饰排除区、平面对象及反馈适配。资产表列职责、尺寸、分层/伸缩方式与图号。 |
| 7. 验收与待验证项 | 用“给定状态→操作→预期”覆盖下表；设计估算、实机风险单列，未运行不得写已通过。 |
| 8. 交付信息 | 日期/版本、固定在线维护地址、同版Markdown ZIP和必要补充来源。 |

短玩法可合并相邻章节，不能漏决策。正文只给当前方案，不保留多套候选、空章、工具命令或“原先采用／现已取消”等修改过程。保留真实未解决风险；历史验证与变更记录压缩到交付说明，不把过期参数带入实施章节。

## 定义一次，按职责引用

- 规则/难度/计分只在规则节定义；按钮提交与判定窗口只在交互节定义；Bot延迟/误判只在多人节定义；矩形/样式/空间映射只在视觉节定义。用稳定REQ编号或参数名连接，概述可通俗复述，验收写可观察结果，不重抄定义。
- 数值标明约束性质：**固定要求**来自用户和系列契约；**推导值**写来源公式并统一计算；**制作初值**可为还原或试玩校准而调整。现有规则作为当前实施基线保留，不能借精简擅改计分、难度或授权范围。
- 新文档的计分节展开普通难度20秒平均15–25分目标的本玩法估算（成功量/周期、每次奖励及失败影响），验收列真人校准项；未实测不声称达标。旧稿按用户授权范围迁移，未应用规则保留在底层维护台账，不能把新稿也推迟到旧稿队列。
- 坐标表负责坐标；材质表负责外观；资产表负责文件、资源职责和对应规格引用，不重复整套尺寸/时序。主文给效果ID、触发、逻辑锁、锚点与清理规则；粒子逐项初值、完整配置、公式和哈希集中到文末技术附录。
- “自包含”指主文、附录和资源包合起来可直接实施，不要求每节或主文独自复制所有资料。附录在主文、参考和验收之后，主文有明确入口；不依赖接手工具已安装Skill。
- 删除重复内容后反向检查：计分端点、失败去向、输入取消、多人权限、Bot行为、背景分层、特效余韵、截止清理仍有唯一且可定位的定义。篇幅减少不能靠删掉这些必要决定。

交付必须展开实际采用的规格、附图和来源，不只说“按Skill”。资产表至少覆盖固定背景、游玩纸面、玩法对象、说明/比分容器、时钟、按钮及库内勾/叉/纸片爆开；采用翻页时加page-turn的容器职责。库资料按[特效库交接](abya-input-contract.md#特效库交接)集中打包；最终字体文件或切片可在资源阶段确定，形态、尺寸和分层不能悬空。

按[固定布局](series-visual.md#固定横屏布局)展开目标分辨率的两栏外框坐标与栏内布局。背景分列BG-01、PLAY-PAPER和右侧UI底板，明确题卡归属、所选BG编号、底纹/边饰与前后明暗关系及资源职责；不以一张带UI示例图代替这些参数。验收采用系列视觉的分层隐藏与原图露边检查。

## UI规格必须在文档展开

所有已确定UI尺寸和位置严格还原[现行布局](play-ui-layout.md)，不能只写“按Skill／见图／居中／自适应”。每份文档的美术UI节必须给下列实施表；表在该文档内唯一维护，其他章节按ID引用。

| 必填表 | 每个实际元素要写明 |
|---|---|
| 坐标与层级 | 元素ID、可见条件、父区域、x/y/w/h、锚点、描边／阴影／白圈是否计入、层级与命中框 |
| 字体与内容 | 真实文本或动态格式、字体／回退、字号、字重、行高、填色、描边色／宽度／缩放及实现方式、对齐、换行／省略；轮数递增事件。倒计时和轮数描边不得省略 |
| 组件与状态 | 素材文件、源尺寸、渲染倍率、常态／按下态共用槽与皮肤共同底边、各态皮肤y补偿、图标可见尺寸及两态中心、焦点／禁用处理；不得沿用共用左上锚点或图标中心上移的旧值 |
| 适配与约束 | 基准视口、支持分辨率、分栏取整、统一尺度、每项位置推导、按钮左下等距与主体两方向净空公式 |

逐项涵盖背景、左右大区域、顶部三项及子元素、实际按钮／白圈／图标、游玩主体、比分标题／席位／头像／名字／分数，不以一张大区域表代替内部明细。固定规格照录，推导值给计算结果；玩法主体尺寸明确为本玩法参数，不能擅自把样例G当通用卡片。

**无按钮时**在表中明确B=null、按钮列宽与额外组间距均不保留，A左右界为P左右各减共同内边距，G.centerX=P.centerX；附实际坐标和上下／左右净空。切换按钮集合时重算各组与A，不能只隐藏控件仍保留偏右布局。

出图使用相同数值并逐项核对，图中仅显示当前玩法需要的组件。按[布局防回归检查](play-ui-layout.md#文档维护与核验)附倒计时/轮数描边近景、按钮常态/按下态对照和底边/中心坐标，确认按下中心下移、白圈与命中不动；不能只交常态整屏图。审批中的特殊按钮在交付回复逐项告知，已审批附依据。所用图片和规格随同版输入包交付，接手者无需安装本Skill即可还原；未做运行验收必须如实标记。

## 一次复核，三个角度

| 角度 | 检查重点 |
|---|---|
| 规则 | 端点、同刻优先级、只计一次分；初始展示和反馈计入总时长。普通真人与Bot的H/D、整题周期C和机会/供给数核算一致。三档由准备页选择且局内锁定，独立答题慢答保留当前题，供题无有限通关终点；二选一与解谜的错误去向正确。推演快准、慢准、常错和乱点策略，并覆盖近期重复、有限组合回退、生成失败备选与套利。 |
| 表现 | 按系列视觉核对背景贴底、平面纸片/四套暖色、分层、可读性与适配。HUD/时钟/按钮一致；交互符合用户的明确选择，其余按默认按钮映射。勾叉与纸片复用库运动并按F1声明平面材质适配，F1到期推进而余韵独立存活；翻页符合容器范围与曝光时刻，不替代成自设计效果或另加等待。 |
| 交接 | 概述、细则、图注、验收及ZIP版本一致。来源可追溯；区别直接复用资产、已认可参考及未选候选。视频链接/片段/关键帧齐全；实际图片及包内相对链接有效。按[同步契约](abya-input-contract.md)回读远端，不能把本地稿或成功请求当作完成。 |

按玩法挑选能区分正确/错误实现的用例，不机械重复全部流程：

- 完整局与重开；成功、失败、未作答、难度切换/锁定、供题跨缓存批次及截止边界。
- 从真实入口增删Bot、满员与权限、Bot真实行动/结算标记、三档行为及旧动作取消；详细预期见[多人规范](multiplayer-bots.md#必需验收)。
- 1人/4席、双端身份与公共/个人状态、迟到/重复结果、断线/离开、同分；同步权威不能靠各端自行计分。
- 从准备到结算/重开完成仅键盘全流程，逐个按钮核对真实映射和左上白圈、Tab/Shift+Tab焦点、快捷键与焦点激活冲突。核对长按、别名/鼠标并用、滑出/跨键/跨题、禁用再启用、失焦、双击、跨页旧按键，以及拖拽不能绕过按钮提交。既有一笔画拖动仍测快速扫过、提前松开及取消；新稿/修订再测规则等价的键盘路径操作，不能遗漏任一方式。持续动作按其例外契约测试。
- F1期间连点、低帧率、静音/减少动态、重复判定、倒计时归零；普通切题保留纸片尾部但不遮新题文字，退出清理。采用翻页时检查单面可见、换面/曝光时刻、缩短后的可读性及中断恢复。
- 四席长名、最大/负分、时钟10/9/0、16:9/16:10/21:9、实际命中尺寸与细路径/数字在纸面上的辨识度；外框符合固定布局公式、四边确实露出原图、中缝不露底，少人时右容器不缩小。

逐项核对已确定的文字与容器，删除自行追加的进度、底部说明和提示条；一笔画网格下方留白。效果图里的额外文字不能成为开发需求，具体边界引用系列视觉。

复检除数值一致外还检查容纳关系：行数×行高＋内边距不超过容器，按钮命中不重叠，派生锚点落在所属区域，缩放后字号/分数/身份仍可读。按[区域边界与等量留白](series-visual.md#区域边界与等量留白)核对各区域边界及游玩主体上下净空，计入描边、底座、阴影和边饰占用，确保上下相等且达到留白初值。参考图负责材质或布局关系，不能覆盖数值规范；发现跨文件位置规定冲突时回到所属模块修正，而非在输出中保留两种指令。

检查发现问题先修稿，仅重查受影响项。最后报告实际通过的检查、保留的风险与未执行的实机项目，不以篇幅变短、请求成功或文件存在代替通过。
