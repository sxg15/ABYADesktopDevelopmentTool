# 全玩法开局 3→2→1 固定切图 · v1.0

2026-11-12 用户原话：“我给你3个素材，严格按右图的位置装到游戏中，我需要你用一段固定的动画，代表321倒计时，放到每个游戏的开头，321不需要缩放，直接切换图片即可。每个游戏都要，位置和大小一定要写死。skill记好后，给我一个压缩包，告诉现在的工程应该怎么更新加入这个功能。”

适用所有现有及新建玩法，每局开始一次，包括单人、多人、带Bot和重新开局。是全局进入正式游玩之前的共享阶段；不在每题、失败重试、阶段切换或断线恢复时重播。此规则为 BR-20261112-001；本轮交付共用接入包，旧游戏工程及旧玩法文档的逐项迁移另记，不能把更新Skill称作已实装。

## 素材与写死的设计坐标

原文件在 [countdown-321-v1](../assets/countdown-321-v1/)，逐文件来源、原尺寸、SHA-256及配置见该目录的 `manifest.json` 和 `countdown-config.json`。必须直接使用原三张RGBA图片；不重绘、不裁透明边、不转文字、不改RGB或alpha、不合成不透明底。3的alpha最大92，2/1最大115，差异来自用户原文件，保留；UI色值白、额外opacity=1、普通alpha混合，不再叠加半透明。

其他分辨率只做共同视口映射：`q=min(W/1600,H/900)`，`offset=((W−1600q)/2,(H−900q)/2)`；数字最终矩形=`offset+q×表内坐标与尺寸`。这仅映射倒计时设计层，不修改其他既有UI布局/四边5px规则，不生成额外黑底。不得每帧或每个玩法另算倍率/位置。若宿主已完成完全相同的1600×900适配，直接用其一次变换，不能再乘q。基准下位置误差≤1px；其他视口按统一映射后取整≤1px。

## 固定时序与可见性

用户只指定321切图，未指定每帧时长；本次明确采用 **每张1000ms、总计3000ms** 的系列默认。以后调整必须统一改规范与接入包，不由各游戏自行微调。

| 权威时间 | 状态/显示 |
|---|---|
| now<C | 已锁局、等待共同倒计时起点；无数字、无题目 |
| C≤now<C+1000 | 3 |
| C+1000≤now<C+2000 | 2 |
| C+2000≤now<S=C+3000 | 1 |
| S≤now<E=S+20000 | 删除数字、显示首题并开放游戏；正式20秒 |
| now≥E | 截止结算，不补播遗漏数字 |

没有0、GO、缩放、弹跳、淡入淡出、位移、闪光、额外音效或停顿。三图预载成功后才发起C；低帧率按当前权威时间直接采样，不用串联三个Wait或按帧计时。数字切换无交叠无空帧。资源没就绪不能启动C，更不能用字体代图。

倒计时沿用本玩法背景/顶部教学/轮数与比分栏；左上正式计时显示20并冻结、轮数1、各席0分。数字在左栏独立覆盖层，玩法题目、棋盘、目标、路线、记忆信息、运动实体和局内操作按钮暂不显示，避免提前观察/操作。倒计时不是对整张画面的灰色蒙层；背景、顶部、比分不额外降透明度。数字不是按钮，无命中/焦点/快捷键圈，可读屏播报3/2/1但不增视觉文本。

## 权威、输入与每个玩法的开局钩子

流程统一为 `Ready → PreStart → Running → Result`。进入PreStart前锁定名单/难度/种子，所有参与端确认必需资源与首题数据可在S就绪，权威发布同一matchId、C、S、E。预生成可在权威端进行，但首题观察信息在S前不得展示给真人/Bot。单人也走相同时间定义；首题观察与玩法自身记忆耗时仍从S开始计入20秒，不被321吞掉。

PreStart时在提交入口和权威处理处双重拒绝所有游戏动作，不排队、不加分、不启动物理/刷题/生成首波障碍/移动/计分任务，Bot不提前规划或启动思考延迟。S时原子撤数字、揭示本玩法首题合法信息、启动原游戏时钟/物理/供题/记忆与Bot延迟，并开放游戏动作；已有键必须先松开再按，旧指针手势取消。Esc仍按该玩法既有退出流程处理，不暂停共同时间；显式退出清倒计时，旧回调不得复活该局。

所有逻辑起点由原先“点击开始/场景加载完成”改到S，截止只用E；若游戏用经过时间，统一`elapsed=max(0,now−S)`。不得把321算在20秒内，也不能客户端各自播完后另开20秒。权威拒绝t<S及t≥E的玩法动作。重复开始包只沿同一matchId/C采样，不重置；重连按当前时间恢复，已经Running不重播；迟到帧直接跳到正确阶段，已过E不能补触发开局。换局/退出取消旧matchId，旧包按现有序号机制过滤。

## 接入与验证边界

纯Lua参考模块 `assets/countdown-321-v1/countdown.lua` 只计算固定布局/状态/时间和一次性阶段进入标记，不声称是ABYA宿主API。制作端将原三图导入现有资源系统，绑定实际UI图片对象、权威时钟、状态机、输入门禁、首题/模拟/机器人启动钩子；未知宿主能力先查当前schema，不能编造路径或接口。

逐玩法验收：首次开局/重新开局均321一次；每题/失败/重连不重播；C−1、C、C+999、C+1000、C+1999、C+2000、S−1、S、E边界；三图同中心/无变形/alpha原样；计时20冻结→S正式起算→E结算；长按/双击/触摸拖入/晚包不穿透；双端与Bot同S/E，后台/低帧率不延时；最小1280×720、1600×900、1920×1080、16:10、21:9核对统一映射。每份迁移须保存当前完整开局图、运行录像与边界日志，静态包检查或Lua测试不等同工程验收。
