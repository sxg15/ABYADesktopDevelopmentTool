# 规则设计方法

仅在新玩法、缺规则或规则重设计时读取。共同约束见入口；文档结构与验收统一见[写作与检查](writing-guide.md)。

## 从参考确定主循环

| 输入 | 处理 |
|---|---|
| 玩法截图 | 保留可辨识的判断技巧与空间关系，补图外规则 |
| 物件/场景/抽象图 | 从对象关系选一个可重复的判断动作，如时机、配对、路线、数量 |
| UI/风格图 | 借组织或材质，自主建立玩法；装饰不自动成为系统 |
| 多图 | 分配玩法、布局、材质、配色职责，不能无区分混合 |

写一句“看什么→判断什么→按什么→怎样得分”，确定初始状态与继续条件。静态图不能证明速度、时长或计分；自行决定但不伪称原作事实。

有视频参考时，按[玩法证据](ui-reference-guide.md)读取片段并交接原链接、关键帧与机制对应关系；先把原作可见行为和本版自主改动分清，再补规则。

## PC交互改编

目标是PC横屏，保留可见按钮，同时按2026-11-11用户要求提供全流程键盘操作及按钮左上白圈提示，映射与焦点契约见[键盘规范](button-system.md#全流程键盘与白圈提示)。未另有明确要求时，手机玩法的滑动、拖拽、划线转换为可见按钮，不改为鼠标拖动；键盘快捷键或透明全屏热区不能替代按钮。明确指定的指针交互保留，并设计规则等价的纯键盘方式；完整定义按下、连续操作、松开、取消、跨题与截止。

| 参考操作 | 本版按钮改编 |
|---|---|
| 大小记忆向上/向下滑动判断 | 固定左「较小」、右「较大」；前值17、当前19点「较大」，当前13点「较小」。卡片上滑动或拖拽不提交、不切题。 |
| 方向滑动或拖动移动 | 用有明确方向含义的按钮控制一步移动或一次滑行，保留原玩法的空间判断；文档确定每次按键的运动结果。 |
| 一笔画 | 指针保留按住鼠标左键拖动盖章，不改为逐格点击。2026-11-11用户明确要求题目固定起点S，初始预盖S，鼠标只能从S按下；键盘直接用上下左右延伸同一路径，不设移动起点焦点或Space开始步骤，keyup不结束路径。完整覆盖自动成功，提前松开、特殊格违规或无合法下一格失败并按F1恢复同题[S]及初始机制状态；局内不依赖Esc重置。固定S与箭头、钥匙门一起生成、变换、求解和去重。两种输入互斥，共用判定；定义快速扫格、失焦与跨题按键保护。局外按钮仍有真实按键白圈提示，不为局内四向输入添加多余按钮。 |
| 其他划线连接玩法 | 默认将可选节点做成可辨认的节点按钮，逐个点击构成路径；用户另有明确交互要求时按该要求展开。 |
| 时机手势或物体拖放 | 时机改为动作按钮；拖放改为选择对象按钮再选择目标按钮，明确确认/取消与结果。 |

保留判断、记忆、路线或时机技巧。含手势参考的文档就近写明来源操作、本版操作及动作结果；按用户要求保留拖动时明确标注该选择，概述、图中说明、判定和验收不能混入逐格点击。默认按钮的提交/取消和外观、所有玩法的统一判定反馈仍由[按钮与反馈](button-system.md)定义；连续拖动盘面的手势另在本玩法展开，局外按钮继续遵循通用提交契约。

## 补齐决策

- 明确内容生成、续供、去重、有解性与最大密度。题目型玩法必须可持续出题；连续动作型持续供应挑战，不为它强造答题界面，不能因预置内容耗尽提前结束。
- 定义成功、失败、漏答、资源消耗及计分信号；估算单次决策时间和整局机会数。
- 选择公共盘面或独立同条件盘面，写清共享与个人状态、随机条件、机会和难度的公平性。
- Bot入口、普通难度及行为按[多人入口与机器人](multiplayer-bots.md)展开；给出本玩法的真人用时基准、具体延迟与失误参数。
- 明确准备、开局、结算、重开、加入/离开/断线；成员离开后是否仍排名必须决定。未知宿主能力写成实施校验项，并给维持体验的处理方案，不编造API。

## PvP主循环与失败去向

统一开局和总局截止，各人按自己的速度挑战，不等其他人、不因慢答自动跳题。当前题等待有效作答；判定后先完成[统一反馈](button-system.md#统一正确失败反馈)，再按以下规则继续。只有总局倒计时控制整局结束，不能将固定题数或某人通关当成结束条件。

| 题型 | 正确后 | 错误后 |
|---|---|---|
| 大小记忆等二选一、错误后答案已失去判断意义的题 | 反馈后换新题 | 反馈后换新题，不重复送分；比较记忆以刚展示的数为下一题基准 |
| 一笔画等解谜、需完整解出才能完成的题 | 反馈后换新题 | 反馈后重置本题操作状态，保留同一题目/布局/难度，重新挑战；不得换题、刷新更易布局或算完成 |
| 连续动作或其他机制 | 明确可判成败的一次挑战及后续状态 | 根据失败是否仍有重试意义确定恢复点，成稿给唯一方案；不得默认所有失败都切下一题 |

部分合法操作（如一笔画选择下一节点）不等于整题正确；定义何时产生真正成功/失败，普通有效点击只给触感反馈，不能每步都弹完成勾。具有真实公共节拍/目标消失的动作玩法保留机制内失败条件，但不额外给独立答题强加单题截止。计分以成功完成量体现又快又准，明确错误代价；不把提交次数当成功数，不因看过反馈而重复计分。

## 持续出题、难度与公平性

- 每个玩法定义简单、普通、困难三档的具体内容生成参数与区别，由准备界面选择，同局真人与Bot共享所选档位，整局保持不变。不是三个连续阶段，不设置阶段题量、升档门槛或随进度提速。二选一有效判定后推进题号，解谜只在整题成功后推进；这些事件都不改变难度。
- 固定T=20秒；设必要初始展示耗时T₀、该档普通玩家完成一题的平均周期C，估算整局机会数约为(20−T₀)/C。C包含观察/决策/操作、必要移动、[F1反馈](button-system.md#统一正确失败反馈)及合理重试。逐档核查有效挑战机会；过长的题简化内容/动作，不延长局长、缩掉反馈或自动跳题。未测参数标为初始估算，机会数不是供题上限。
- 任一档的缓存批次耗尽后都生成下一批同档新题，不循环播放完全相同的那一批。使用确定性生成器或充足的经校验模板与变体，提前准备下一批；生成重试要有上限与同难度有效备选，不能卡在空白加载或无限找题。预生成数量只是缓存，不是总题数上限。
- 为每种玩法定义题目指纹与去重范围，优先单局不重复，至少避免相邻重复及短期重复；记忆题对比较关系/数字组合去重，不禁止合理的单个数字再次出现。有限组合空间不足时先用合法变体、再在用尽后洗牌且避开近期题；不得为追求绝不重复生成无解/越界题，也不承诺数学上无限唯一。解谜失败回到原题是有意重试，不算供题重复。
- 独立题目型玩法：真人与Bot使用同局种子、同难度、按个人题号对应的序列；快者先看后题，慢者保留当前题，只发布各自已解锁内容，重试不消耗出题随机状态。共享盘面或连续动作玩法则明确共同事件序列、冲突判定与机会分配，不机械套用个人题号。两类都不能通过失败刷新或临时调难度偏袒某席。
- 三档主要通过判断/空间复杂度、干扰或动作要求区分，最多一个主要维度加一个次要维度，每档都有明确范围和上限；内容变换保持在所选档范围内，不随题号持续增加难度，不给独立答题加单题倒计时。

## 速度、准确率与策略检查

所有新设计须按生效底层规则核算普通难度普通人类玩家20秒平均15–25分的目标。给出本玩法成功单位、每次奖励/失败代价、完整周期和成功率假设，区分制作估算与真人样本；具体方法见[得分校准](../../abya-foundation-rule-maintenance/references/scoring-calibration.md)。旧稿的适用清单与迁移状态由该Skill管理，未授权时不自动批改。

在同一难度内推演慢而准、快而准、快但常错与随机乱点的单位时间得分，计入反馈、计分与重试成本；快而准应优于慢而准，乱点不能靠提交量取胜。二选一尤其检查猜测收益，优先用出题与明确的计分/扣分规则处理，并同步概述；不额外增加等待来改变F1切题时序。排查重置、刷新和重复计分套利；解谜重试成功只计一次，不混排不同难度的历史成绩。

二选一记忆还要检查只看当前值的统计猜法；相邻小变化只能减少线索，边界仍可能泄露方向。按钮化降低动作成本后重估收益，修正具体规则而非追加“防作弊”。

数值与模拟只验证一致性，不证明乐趣或平衡；把需要实机观察的风险写入当前文档。
