# 从参考到开发文档

从图片、玩法参考或简短想法补齐一个确定的ABYA玩法方案，先展示本玩法局内图，再交付飞书开发文档和同版输入包。本技能负责设计与文档维护，不执行游戏制作或代替实机验收。

## 共同约束

- 1–4人，真人与Bot合计最多4席；单人可独立玩，不强制补Bot。开始界面必须有“添加机器人”。普通Bot操作稍慢于普通真人。
- 单局固定20秒，首题观察和反馈计入总时长；截止立即结算。计分制，最高分获胜，默认同分并列、单人显示得分、失败后继续。普通难度普通真人完整20秒平均得分目标15–25分；按玩法估算并留真人校准项，不当保底/封顶，不统一套每次5分。
- 所有玩法每局正式开始前统一播放用户原图3→2→1，每张1秒直接切图，无缩放动画；固定位置/尺寸/原始alpha及多人起点按[开局倒计时](references/start-countdown.md)。这3秒不占正式20秒，结束才揭示首题、开放输入和启动Bot，不按每题或重连重播。
- 准备页选择简单／普通／困难，默认普通；同局统一、开局锁定，局内不自动升降档，挑战持续供应至截止。
- 全流程可只用键盘完成；所有按钮有左上白色真实按键提示。保留可见按钮及用户已指定的指针交互，暂不设计手柄。
- 仅游玩界面使用指定按钮、顶部容器和固定内部布局；准备、结算等不套用本套内部UI。全部UI尺寸、位置、字体及状态按[现行布局规格](references/play-ui-layout.md)严格还原，并在每份开发文档中展开。有按钮时左下等距起排；无按钮时按钮区完全不存在，游玩区在整个左侧大区域内左右居中，垂直方向仍避开顶部UI。
- 视觉采用固定原图R15和暖色平面纸片主题。只显示有职责的内容，不擅自添加进度、提示条或补充文字面板。特殊按钮在每次文档交付后告知用户，直到其明确审批通过。
- 正误判定复用指定特效库运动，采用平面材质适配；判定窗口与纸片余韵分离。具体时序由交互规范定义。

优先级：用户最新明确要求＞现行规范＞参考图指定职责＞原作或历史稿。区分固定规格、公式推导、玩法专属设计初值与实测结果；历史预览上的“待微调”不允许覆盖现行数值。用户提到小鸟时读取[四只小鸟原型](references/bird-characters.md)，保留所选身份；单款选角不自动成为系列默认。

用户授权偏好（2026-11-12）：“可以的，我用目标模式时，可以不用询问我”。在用户已授权的目标模式任务范围内，自行完成具体方案、同步与核验，特殊按钮随每份交付告知，不再逐项询问或以等待单项审批阻塞队列。记录这是目标模式执行授权，不伪称用户已逐图审美验收；非目标模式仍按原特殊按钮告知/审批约定。该次原话同时明确批准见缝插针v3.9圆形Space插针按钮。

## 执行路径

1. **读取当前状态。** 实际看用户图片／文档，读取[底层维护台账](../abya-foundation-rule-maintenance/SKILL.md)生效规则及该文档状态。新稿直接落实；旧稿只处理本次授权范围。修订现有交付稿先读远端最新正文，保留用户改动。
2. **确定方案。** 补齐规则、输入、多人和视觉；涉及反馈时实际读取[特效库](../abya-crayon-paper-effects/SKILL.md)素材与参数。确定实际按钮集合，再按布局公式计算坐标，无按钮不留空列。
3. **先展示局内图。** 新稿及影响呈现／交互／布局的修改先制作并在对话展示本玩法完整局内图；落实用户反馈再交付完整文档。具体按钮规则维护逐玩法展示，不能用通用模板、旧图、单按钮图或仅链接替代。
4. **成稿与复核。** 按写作指南交付单一方案，逐项写明UI的数值、位置、锚点和适配公式；图、文、资源包一致。核对有／无按钮分支、倒计时与轮数的可见描边、按钮两态底边固定且图标/文字中心下移；具体值及证据要求只在游玩UI布局维护，不能沿用历史图的左上锚点。特殊按钮单独报告审批状态。文档检查不等于实机通过。
5. **同步与记账。** 默认同步飞书并交付同版Markdown ZIP；回读验证正文、图片和输入包后登记实际已应用规则版本。受阻保留成果并说明未同步项，不能将部分交付称作完成。

仅整理Skill或登记规则时不自动改写旧玩法文档。旧稿仍按台账排队，Skill更新不等于已迁移。
