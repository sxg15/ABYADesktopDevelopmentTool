# 可复用运行测试

初始化异常时先保存完整原日志；用 [日志摘要工具](../scripts/summarize-runtime-log.mjs)
归并重复异常并保留首次位置、末次位置、次数和有限堆栈。先查第一条异常与启动报告，
再查退出清理错误；最后100条日志可能只覆盖刷屏的几百毫秒，不能替代整个启动过程。

使用随包 Node 执行 [runtime-scenario.mjs](../scripts/runtime-scenario.mjs)，不为每个游戏重写
CLI 连接、轮询、断言和回执管理。运行目录必须在当前任务内；脚本不启动或停止实例。
先发现实际能力并核对实例/存档/构建，不把下面的动作名称当成平台 API。

## 六类复用流程

| 场景 | 映射到当前游戏的动作 | 必须观察的结果 |
|---|---|---|
| 单人闭环 | 准备、开始、合法输入、等待结束、返回 | 阶段顺序、权威结果、再次准备 |
| 双端同步 | 房主开始、客户作答、重复请求、两端读取 | 权限隔离、同题序、计分一次、相同结算 |
| 输入边界 | 阈值两侧输入、卡外起手、横向输入、reset、跨状态释放 | 合法输入生效，其余不提交；真实 OS 失焦单独记录 |
| 固定序列 | 在独立夹具中注入已知序列、正确/错误作答 | 明确预期分数、错误后基准；最后移除夹具并冷加载 |
| 机器人 | 按批准档位和人数准备、开始、读取权威行为 | 实际被接受动作、反应和成绩；受控函数测试不冒充比赛 |
| 保存重载 | 保存并记录指纹，另行托管冷加载后读取 | 相同目标与代码、无夹具残留、完整闭环 |

相同构建且无影响的检查复用已有证据及其来源；不冒充重新执行。
游戏变化只更新 scenario 参数/断言与能力映射，保留公共执行器。

## 输入格式

新场景可以使用 schema `abya.runtime-scenario/v2`，必须包含至少一项实际可观察断言。
只读步骤可设置 readRetries=0–2；执行器先通过实际 capability 描述核对 ReadOnly，不能仅靠自填标签重复写入。
回执区分 invocationRejected、verificationUnavailable、assertionFailed、needsReconciliation。
明确的派发前参数/身份拒绝不等于未知写入；未知写入仍先对账，任何分类均不自动诊断 PB 缺陷。

## Player 基线

在任务托管终端使用 `node <scripts/player-baseline.mjs> read`，读取与实际选定 Player 完整指纹匹配的共享基线。
默认只返回摘要和详细资料路径，避免把完整能力目录塞入上下文；`read focus` 等关键词最多返回 20 项匹配的能力摘要，实际参数仍从当前实例按需发现。
基线不存在时不构成游戏故障；使用当前能力目录和最小验证继续，不在每个项目重新审计整个 PB。
发布包资格验证任务可在运行实例仍存在时执行 `node <scripts/player-baseline.mjs> record <实例ID> <已完成测试ID...>`。
后端直接读取原生报告，拒绝空断言、未完成或失败报告，并核对前后完整构建指纹。
记录包括实际能力目录与列明的运行验证；已发现能力不代表全部已测试，基线不替代当前游戏的要求验收。
同构建基线可供其他任务按需读取，源码调查须有当前构建上的可复现反例，不能仅凭能力发现失败。

## 场景输入示例

```json
{
  "schema": "abya.runtime-scenario/v1",
  "version": "实际已登记版本",
  "buildHash": "已核对构建指纹",
  "archiveHash": "已核对存档指纹",
  "capabilities": ["从本实例目录核对的能力名"],
  "steps": [{
    "id": "verify-authoritative-score",
    "instanceId": "任务拥有的实例 ID",
    "toolName": "从本实例目录核对的能力名",
    "arguments": {},
    "assertions": [{"path": ["实际结果字段"], "equals": 5}],
    "readOnly": true,
    "repeat": 10,
    "intervalMs": 500
  }]
}
```

这里只是格式示意，必须替换实际能力、参数、目标和预期结果才可执行。
assertions.path 相对于 CLI data；工具只返回 content 时须按实际结构映射，不推测成功。
写操作不重复。仅明确 readOnly 的读取允许有限轮询，不能把写操作伪装成只读。
默认单次60秒、最大120秒。失败/超时停止本场景；外层工作队列继续独立场景。

在任务托管终端运行：`node <脚本绝对路径> <scenario.json> <任务内新运行目录>`。
持久化请求 ID 在派发之前写入。完成项只复用同一输入回执；失败或未知项拒绝自动重放。
崩溃留下 running.lock 时，先核对原进程和操作回执；不得用新目录绕开未知结果。
回执保存结果 hash 与指定断言，不复制整个响应。绑定 hash 由调用者实际核对；脚本不会
凭这三个字符串证明存档未变化，也不会把测试结果自动填成游戏验收通过。

## 结果登记

每个场景结束即保存证据并用 record-validation-run 登记实际完成的检查，而不是最后
重新整理所有历史。仅能证明局部断言时不要登记整项 passed；截图仍需实际查看。
同一 runId 绑定版本和 checks，使用 production batch 登记证据、视觉与验证结果。
批次已应用项按回执保留，首个失败后的项单独修正；不重跑整个测试或登记批次。
