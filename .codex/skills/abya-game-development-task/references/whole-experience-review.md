# 8＋4 整体迭代

仅在完整制作流程已完成 R0，或用户明确要求本阶段时使用。局部排错和报告阅读不新增轮次。
轮次、全部维度、题库及关键版本从 [流程配置](../assets/production/workflow-policy.json) 读取，
记录契约见 [任务资料](production-records.md)。规则有版本，任务续做不重置已有轮次。
完整过程取证按 [实际录像](recording.md) 使用随包录制工具，并核对画面和版本。

## 开始条件

需求和计划已确认，R0 完成约定内容、现有素材及真实完整循环，已保存并核对实际版本。
保留 R0 完整自然循环录像及页面/关键状态截图。必要取证工具不可用就记录阻塞，
不拿静态截图替代完整过程，不伪填 reviewed 或测试成功。
大改任务检查改动及其影响的完整体验，保留用户要求不改的内容。

## 每轮怎么做

1. 固定输入版本、环境、实例身份和需求范围，创建本轮记录，状态 in-progress。
2. 重新运行并检查全部适用维度、页面、关键状态和动作，保留巡检/动作证据。
3. 记录问题和反例，修复后验证影响范围；版本改变记录本轮输出版本。
4. R9—R12 每轮还回答全部功能与视觉题，逐题关联真实证据、反例、问题、修改和复验。
5. 核对本轮覆盖、问题关闭和证据有效性后才关闭本轮；无缺陷也保留实际检查依据。

每轮都是整体检查，可以变化操作顺序、输入时机、密集数据或身份扩大覆盖，
不能按“规则、字体、材质”等拆成十二批。失败和重复复验留在当前轮，不算新轮次。
相同运行中目的完全相同的专项检查共享结果；不能把上一轮资料复制为本轮执行。
不适用写具体原因；缺环境、缺证据或没执行写 not-run/blocked，不能写不适用。
本轮缺陷未复验关闭就不前进；真正新增范围另走需求变更，不自动缩减原验收目标。

## 证据与问题

R0/R8/R12 留存完整自然玩法循环录像与页面/关键状态截图，保持同状态同视口对比。
各轮保留实际操作、截图/动作片段、状态断言、错误日志及修复前后依据。
实时录制、连续采帧、AI操作、脚本真人席位输入与人工试玩分别标注。
实际打开图像、观看动作过程，记录查看范围/时间点；文件存在不代表已审阅。
有可观察的规则状态就使用断言，不能仅由界面或“无报错”判断。

单机、联机、Bot 按确认范围检查；联网必须真实 Host 加独立 ClientOnly，
桌面模拟目标视口不等于手机真机。已有 Bot 专项报告引用同一运行证据，不另造通过结果。
旧证据能否复用按版本、环境、依赖和检查目的判断，受影响则标 stale 并复验。
素材、交互、文字和动态反馈按已确认要求检查，不借评审擅自增加美术生产。

## 关闭与交付

R12 从最终候选冷启动，证明保存重载后可完成循环；仍有必要缺陷就保持当前轮未完成。
反复失败时记录已尝试方法和恢复条件，不无限盲试，也不因十二轮结束自动判合格。
每轮记录 inputVersion、outputVersion、环境、全部检查、证据、缺陷、修改与复验、
知识采用以及耗时；后四轮逐题填写，未执行或未审阅不得批量标 passed。
达到自检要求后提交交付候选，用户确认仍是独立决定。报告生成不更改任务完成状态。
