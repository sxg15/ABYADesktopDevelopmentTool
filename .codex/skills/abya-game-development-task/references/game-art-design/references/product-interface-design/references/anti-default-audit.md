# 结构、平台与默认风格审查

完整设计在选型前检查结构，完成后对真实渲染再检查一次。局部改动只检查关联部分。
记录“观察 → 产品依据 → 保留/修正/淘汰 → 证据”，不用自评分数或关键词计数代替判断。

## 方案阶段

| 检查 | 实际操作与判断 |
|---|---|
| Grayscale Test | 暂时忽略品牌色、渐变、阴影、纹理与装饰，比较空间、尺寸、顺序和信息关系；三个候选应仍有结构差异 |
| Logo Swap Test | 移除 Logo、名字和营销文案，尝试替换成无关产品；若主任务区、导航和关系仅改文案便成立，检查是否缺少领域依据 |
| Platform Swap Test | 假设改用触摸、鼠标键盘或遥控器；指出布局、焦点、输入、密度和状态恢复必须变化的位置，不能把缩放或 WebView 容器当平台适配 |
| Genericity Test | 检查五个产品专属决定是否来自真实任务、关系和控制；“看起来专业”不构成依据 |
| Container Removal Test | 忽略卡片背景、阴影和圆角，检查分组、排版、对齐、缩进、位置与连续结构是否仍清楚；每项一盒与层层套盒需要实际理由 |

这些是诊断，不是机械禁令。标准控件与通用设置可以保留成熟结构；跨平台共享部分也应保留明确依据。
灰度不能抹掉产品本身依赖的内容：地图、绘画或颜色玩法应保留轮廓/编号/关系作为结构诊断，另在正常颜色下验证功能。
判断对象是完整主任务与信息架构，不因一个通用按钮、表格或登录框便淘汰产品。

## 运行后的 AI Default Audit

检查以下是否无依据地成套出现，并逐项解释其产品职责：

- 营销组合：眉题、巨大标题、诗意副标题、双 CTA、三张功能卡、英文小标签、虚构数据。
- 管理后台组合：Sidebar + Topbar、面包屑、搜索、头像、统计卡、标签页、表格和通用空状态。
- 风格替代品：全绿/全紫等单色覆盖、黑底荧光、Bento、磨砂、大面积模糊、发光边框、随机噪点、贴纸、巨大数字、滚动炫技。
- 组件库痕迹：每项配同样小图标、统一卡片外框、统一圆角/间距、默认字体和大量无任务意义的辅助文字。

出现这些元素时不要立即删除。保留有产品理由的部分，重做缺少理由的结构；换成另一套流行风格不算通过。
组件库可以提供焦点、菜单、弹窗、可访问性与状态行为，其默认皮肤不自动成为产品审美。
颜色分别说明内容、状态、危险、成功、选中、结构、品牌和领域职责；内容已有丰富色彩时避免主题色压过内容。
字体从操作/阅读、中文/数字/代码比例、使用时长、密度和回退决定；不把特定字体或超大粗体标题当万能方案。
图标用于识别、状态和工具含义；文字足够清楚时可以没有图标，不为去模板感破坏必要的一致性。
逐句做文案删除测试：删除后是否影响识别、理解、操作、决策、纠错或确认？无作用的填充文字应删除。
动画应解释因果、状态、层级、对象位置或反馈；关闭后毫无损失的呼吸、漂浮、弹簧和依次飞入需要重新判断。

## Genericity Audit 与 Product Recognition Test

核对领域结构、五个专属决定、真实内容占比、导航依据、密度、色彩职责、容器依赖与平台输入影响。
检查把产品换成 CRM 等无关软件后哪些部分会立即失去意义；若整套主任务仍合理，返回信息架构/导航/交互层修正。
隐藏 Logo、品牌名与营销文案后，保留真实内容、媒体、控件和关系，检查能否识别产品类型，而不只是“某种 Dashboard”。
若进行了真实人工识别测试，记录对象、看到的版本和回答；只有 AI 自检时明确标注，不能虚构用户认可。
产品类型易识别是目标，不要求每个界面独一无二、最炫、最复杂或最实验。

## 内容与连续行为复验

使用实际可能出现的长短标题、缺图、不同图片比例、多语言、重复名字、0/负数/大数、缺失值、少量与大量内容；不编造均匀样例美化截图。
覆盖适用的首次、空、正常、加载、错误、离线、权限不足、选择、禁用、焦点、成功和危险操作状态。
空状态说明为何为空、下一步可以做什么、未来会出现什么；不能一律只给图标和“暂无数据”。
操作实际点击、拖动、多选、键盘路径、返回、退出、撤销/重做、错误恢复和长任务反馈；不为不适用项目造功能。
跨平台检查 URL/刷新/深链接、输入法/安全区、分屏/窗口调整、触摸/手写笔或遥控器焦点等真实行为，而非仅截图缩放。
