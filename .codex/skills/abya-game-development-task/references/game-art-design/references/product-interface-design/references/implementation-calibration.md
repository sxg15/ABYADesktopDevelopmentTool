# 从概念到可执行规格与实机标定

用于把已选设计实现到产品、处理字体/尺寸/间距偏差，或承诺精确还原时。局部修改只覆盖受影响对象；不重开结构选型，不增加人工确认点。将内容合并到现有设计、计划和验收记录。

## 先区分三种成果

- 概念图：说明气氛、构图和视觉意图。生成的字形不等于可用字体，图中的边界也不等于实现参数。
- 可执行设计基准：用目标平台可取得的字体、独立控件和实际资源重建代表画面，标出尺寸与约束，说明与概念的差别。
- 实机结果：由目标应用/引擎实际渲染和操作取得，绑定真实版本。浏览器排版样片或独立动效样片仍是样片，不能冒充引擎运行证据。

概念尚未选定时先探索；选定后再标定。概念中不能实现的字体或形态须明确替代及影响，沿用当前文档修订流程；不能为让对比通过而悄悄修改已确认基准。只改背景时保留已确认操作层，不重新生成整屏破坏它。

## 一份规格驱动实现

先确定基准画布、坐标原点、设计单位、截图像素、窗口/DPI/缩放、安全区、相机与目标比例之间的关系。记录原图尺寸和实际资源尺寸；缩放显示到目标尺寸不等于原生资源已经达到该分辨率。

为影响主任务的对象保存稳定 ID，并记录：

| 对象 | 可执行规格 | 标定证据 |
|---|---|---|
| 文本/数字 | 可用字体文件或平台资源 ID、字重、字形/斜体、回退；字号参数、自动字号开关及范围、行距、对齐、基线 | 相同样字的实际渲染；可见字面高度/宽度、基线、笔画粗细及回退情况 |
| 布局/容器 | 外框/内框、内容区、边距、行列间隙、对齐线、边框/圆角、锚点与伸缩规则 | 注明测量口径的边界图或几何读回及截图；不要混用外边缘、中心距和净间隙 |
| 资源/图层 | 原文件身份、像素尺寸、裁切/拉伸/切片、透明度、显示范围与层级 | 最终显示尺度；背景蒙版、操作层、文字层各自受影响范围 |
| 状态/动效 | 触发对象、起点、数量/密度、大小、时序、轨迹、结束/打断、叠放顺序 | 对应输入与关键时刻/视频，不以“出现了”代替表现一致 |

用任务内 JSON、设计变量或现有配置作为实现的数值来源，布局脚本/组件读取同一份数据；避免设计文档、生成脚本和运行脚本分别手填三套数值。记录规格版本/摘要与实现读取位置。条件分支保留命名，变化后重建关联对象。

例如网格总宽是 `列数 × 格宽 + (列数 - 1) × 净间隙`；内框边距另算，描边是否计入宽度必须一致。对象数量、内容密度或窗口比例变化时，为每种布局模式定义规则，不能默认固定 gap 在所有模式下保持相同疏密比例。

## 字体先匹配，再校准字面大小

先在当前运行包验证实际可用字体、字重/斜体与字符覆盖，再调整字号。不要用不断放大字号补偿错误字形，也不要把代码里的 fontSize 当作截图中的字面高度。
样字来自真实内容：中文/数字/单位混排、窄宽数字、多位数、倒计时边界、长短名称等，选覆盖当前产品的组合，不强制某个固定样字集。
比较同一文本的字形、笔画、倾斜、基线、可见高度和视觉重心。记录字体资源与回退、父级缩放、自动字号和单位换算的实测结果；没有证据时，不把差异统归某个字体或引擎接口。
资源和字体已可验证时，尽量用真实字体排版代表稿；生成图片中的假文字不作为承诺“一比一”的依据。尚无运行条件则标为待验证，先完成不依赖该结果的设计内容。

## 先标定代表片段，再扩展

实现授权生效后，先在目标平台做最小代表片段：主任务操作区、主要文本层级、一个关键状态及必要装饰，足以发现系统性的字体与尺度问题。
核对原始要求、规格、截图后修正关键偏差，再复用到其他页面/密度/状态。它是已有实现阶段内部的验证点，不是新增审批，也不要求先实现整套玩法或精修所有装饰。
更换字体、修复字号接口、调整自动字号、锚点、画布缩放或导入资源后，复验受影响代表场景；“脚本不报错了”不代表画面已经对齐。

## 同条件对照与误差解释

1. 保留原始基准与实机文件，记录版本、像素尺寸、内容、状态、镜头和捕获时刻。不同题面/文本/人数/状态只能做定性审查，不能据此给全画面还原率。
2. 对齐游戏视口/内容区域的坐标；同宽排版不是配准。等比例缩放、裁切原点与遮罩均有记录，不能独立拉伸元素去掩盖误差。响应式重排要与对应布局基准比较。
3. 提供基准、实机、差异材料。差异可以是有标记的叠图、边界/样字测量表和观察说明；只有拿到可比图像时才做像素差异。测试浮层、数据变动和动态粒子的排除区域注明原因，不能掩掉待检文字/边框；动效另用相同触发和时序验证。
4. 几何、字体、颜色/材质、动态表现和交互分别下结论。边界误差小不能证明字形/笔画相同，特效播放成功也不证明大小、密度、轨迹匹配。
5. 阈值写明基准、单位、适用对象、来源和待验证/已约定状态。2 px、5% 等仅可作为具体任务的候选值；由目标平台、可读性和已确认要求决定，不能默认应用到所有项目。

需要核算手工或运行工具测得的数值时，可复制 [测量模板](../assets/calibration.template.json)，按 [工具说明](calibration-tools.md) 使用 compare-calibration.mjs。它计算已提供测量的偏差并检查文件身份；不自动找字、识别边界或判定美术通过。
缺少实际图、未配准、基准不一致或关键测量缺失，应标为未验证；超出约定值标为差异，不得填 matched。尺寸测量仅支持被测项，禁止推出任意“还原率”。

## 修改与交付

每次修复列修改项、保护项和回归范围；例如仅改背景对比时，操作层几何/字体应保持原值并检查保护区域。接受的差异须有具体依据，不把“试玩通过”扩大为“所有美术一致”。
记录功能完成、视觉质量、规格还原、人工认可各自的范围与版本。未验证字体/尺寸或尚存关键差异时，可以交付可玩版本并如实列缺口，不能声称完美还原。
案例经验应保留可用字体、规格来源、实际测量、失败原因及修正范围；漂亮概念图只能作为设计参考，不能被复用为已验证实现。
