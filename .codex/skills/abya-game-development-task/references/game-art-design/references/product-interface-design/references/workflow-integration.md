# 接入已有 AI 设计与开发流程

先读取现有工作流、模板、技能分发方式、版本约束与实际输出。只读分析、设计提案、实施与发布是不同范围，遵守用户本次授权。
本 Skill 提供设计判断，不替代宿主项目的状态机、工具契约或用户审批。

## 分层职责

- 通用设计约束：产品任务、交互、平台适配、视觉推导和证据标准，与具体品牌及引擎无关。
- 项目设计依据：领域对象、用户任务、设备、内容、既有交互和可实现边界。
- 可选风格/资产模板：用户已选择后提供字形、材质、图形和资产规范，不能倒推产品结构。
- 实现与验证适配：宿主平台的组件、导入、绑定、运行、截图和状态读回。

不要将“通用约束”伪装成一个默认美术风格选项，也不要把所有资产模板强制加入每个任务。
整目录复制本 Skill 可保留所有相对引用；接入其他执行环境时明确入口与资源加载规则，不依赖个人电脑的绝对路径。

## 映射到现有阶段

| 已有阶段 | 补充的设计内容 | 可审阅证据 |
|---|---|---|
| 需求分析 | 用户、主任务、领域对象、设备输入、频率和约束 | 事实/假设与主任务流程 |
| 美术需求/方案 | 信息结构、交互状态、参考分析、视觉语言、资产范围 | 带真实内容的结构图或原型，以及决定依据 |
| 实现计划 | 代表场景、复用与新增、资产规格、平台适配、验证动作 | 可执行步骤与每步完成条件 |
| 制作实现 | 先完成主任务的一段完整流程，再扩展 | 可运行场景及关键状态 |
| 自检与反馈 | 对照同版本方案查看运行画面并实际操作 | 具体问题、影响、修复和复验记录 |
| 交付 | 对照约定范围收束设计与实现差异 | 已实现/未验证项及对应证据 |

沿用已有确认点，将资料补充到既有文档；不默认增加“风格批准”“线框批准”等额外等待。
有人工批准时，批准绑定具体版本。设计自评、检查脚本、参考图片和生成概念图均不能代替用户批准。
若宿主工作流限制现有任务自动更新，应提供明确升级路径，不悄悄覆盖已固定的技能和方案。

## 判断流程是否真的改善

用同一真实任务、内容和设备比较改前与改后的设计决定及运行结果，不能只比较提示词长度。
检查是否仍从风格形容词开始、是否实际查看参考、是否先做核心场景、是否有可操作状态和运行证据。
模板字段和文件存在只能证明资料齐全；不要用机械字数、关键词或自评分数宣称美术质量达标。
对薄弱环节修正一次可观察的决策规则，不为每个失败样例永久新增一条全局禁令。
