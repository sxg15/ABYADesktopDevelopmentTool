# 资源与方案阶段的技术预检恢复

仅适用于当前已批准需求范围内的 resources/plan 技术预检，不提前进入玩法实现。
流程2.6可在有实际Runtime调用失败时派发有限恢复；同阶段同需求范围最多两轮，各10分钟。
时间预算在安全检查点生效，在途操作先完成或对账；旧任务升级后，用户可从原子流程继续
入口请求有界诊断，但不能据此重置已耗尽的自动恢复预算。
不靠换问题ID、改摘要或重建存档重置预算。不跳过人工问题、文档审核、复验或用户暂停。

先区分三层：APP会话授权、Runtime CLI是否响应、游戏编辑上下文是否就绪。
`Creator archive did not finish loading within 300 seconds`是工具自身返回的加载失败，
不是证明CLI短连接中断。冷启动报告launching/worldReady=false也不等于传输根因。

1. 超时先读实际存档/关卡、加载标志、操作队列、未保存状态及原请求收据。
   ArchiveLoaded但无关卡属于部分完成，不重新建档。未知写入先对账，不重放。
2. 两次只读CLI超时且无进展，改查托管进程、磁盘启动报告和原始日志；不堆叠主线程查询。
3. 对当前任务专用预检实例，只有无未保存内容、无未知写入且原进程确认退出，才能按
   原存档和准确关卡干净启动。包含首次失败的冷启动，总共最多两次；不接管用户试玩窗口，
   不自动强停无法证明安全的实例，不改宿主源码或启用内存自动停止。
4. 核对本次启动身份、ready/success/worldReady、实际archive/level和contentLoaded。
   界面面板前置条件先查当前可见入口，从真实原生按钮进入；不复用失效组件ID或猜坐标。
5. 恢复后更新原问题、实际证据和当前摘要，注明历史结论已被本次恢复取代，继续剩余
   字体、素材、布局、命中与能力预检。一次成功不等于宿主根因已修复。
6. 预算耗尽、无安全恢复条件、需新权限/文件或用户决定时，保留成果与具体恢复条件。
   不把未测项写通过，不批准文档；旧故障报告保留，但不重复当作当前失败事实。

通用已观察案例：空白标定存档热加载后停在ArchiveLoaded，首次冷启动未就绪；原进程停止、
后续同配置干净启动可能恢复。案例只支持这条有界诊断路线，不能保证所有机器都能恢复。
不要为参考案例放宽跨任务权限、复制他人存档、凭据或动态实例ID。
