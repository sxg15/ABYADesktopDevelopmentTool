# 底层规则批量维护

管理跨玩法规则的生效与旧稿迁移，设计/修改正文仍使用对应玩法Skill和飞书文档Skill。本次用户选择单独的飞书台账；旧玩法文档不嵌维护区，不因记账或查询而改写。

## 入口与事实来源

- 当前生效规则、适用文档、逐条应用记录和台账地址都在[持久台账](state/ledger.json)。先用 `scripts/ledger.py query` 或 `rules` 读取最新数据，不依赖聊天记忆。
- 当前规则包括：普通人类玩家在普通难度完整20秒的平均得分目标15–25分；所有玩法全流程可只用键盘完成，每个按钮左上使用白色圆形真实按键提示；仅游玩界面统一采用用户提供的圆形/方形按钮常态与按下态素材（准备、结算等界面除外），并统一游玩界面左下按钮键位、顶部三项、等距和特殊按钮审批要求。详细边界以台账中对应规则版本为准，素材见[按钮来源](../abya-gameplay-brief/references/button-assets.md)。
- [维护流程](references/workflow.md)定义状态、证据与线上同步；[得分校准](references/scoring-calibration.md)用于估算和验证目标，不代表已实测。
- 全玩法开局321规则BR-20261112-001使用[固定切图规范](../abya-gameplay-brief/references/start-countdown.md)：原三图、固定中心/尺寸、各1秒，正式20秒前执行；记录规则及共用工程接入包不等于旧稿或各游戏已实装。

## 两条执行路径

**新文档：** 设计开始前读取全部生效规则，直接落实到规则、页面/输入、局内图、验收和输入包；不把新稿放入“等用户批量维护”的旧稿队列。交付后登记文档与逐规则证据。缺少真人数据只影响“体验验证”字段，不能伪称目标已实测达成。

**旧文档：** 新规则登记/换版时，为已登记且适用的旧稿建立新版本待处理记录。用户说“记住、先排队、暂不修改”时，只更新Skill、状态及专用台账；用户明确说执行维护时才按其范围修改原文档。不因新规则已生效而后台自动迁移旧稿，不创建定时自动改稿任务。

## 常用动作

- **登记底层规则：** 保留用户原话、确认日期、范围、版本、验收点和新稿生效策略；同义规则先合并，变更已有要求则递增版本，保留旧记录。不得把滑冰每关5分推广为所有玩法每次都加5分。
- **查询：** `python scripts/ledger.py query --document "滑冰或文档URL"`；也可按 `--rule` 查询。回答列规则版本、应用状态、下一步与依据，附专用台账/对应分节链接。未登记的链接先解析真实文档ID，再登记并匹配适用规则，不能回答“没有待办”来代替未覆盖。
- **迁移：** 只在用户授权的规则/文档集合内读取最新正文与版本，保留其他改动；使用玩法Skill完成规则、配图、输入包和回读核验，逐份落账。一份失败不把其余一并标完成；不依赖源更新或其他仓库工作流。
- **按钮维护出图：** 执行BR-20261111-003时，每次必须制作并在当前对话展示本次游玩界面布局图；批量按玩法逐份展示，记录图片版本与展示依据。同时核对现行UI的固定尺寸／坐标、文档自包含规格、无按钮取消空列并在整个左栏水平居中、六态素材及特殊按钮审批；补倒计时/轮数可见描边近景和按钮两态底边/中心坐标，按下中心必须下移，具体参数只在游玩UI规格维护。未展示不能标已应用；仅登记/查询/修改规则不自动出具体玩法图或迁移旧稿。
- **目标模式授权：** 用户于2026-11-12明确“可以的，我用目标模式时，可以不用询问我”，已授权目标范围内按玩法Skill自主完成具体方案、云端同步与核验；特殊按钮随交付告知，不再逐项询问或等待单项审批来阻塞维护。保存授权原话与范围，不把执行授权等同逐图审核或实机通过；同次已明确批准见缝插针v3.9圆形Space插针按钮。
- **状态更新：** 用 `set-status` 记录；仅更新Skill、只写本地稿、只请求成功或只改正文未更新必要输入包都不算已应用。线上回读及同版交接齐全后才标 `applied`；规则换版后旧版已应用不能抵作新版完成。
- **台账同步：** 注册/状态变化后，读取并保留专用飞书台账的人工备注，更新其中受影响的规则/文档分节。写入结果不明先回读，避免重复新建；普通查询不写远端。不要改旧玩法文档来展示队列。

## 工具与交接

脚本只处理本地持久状态及生成XML，不会自行修改飞书或玩法正文。CLI参数见 `python scripts/ledger.py --help`；测试可用 `--state` 指向隔离文件。正常运行保持默认状态路径，不把临时副本当长期台账。

完成时分别报告“规则已生效”“旧稿已应用/待处理”和“真人验证”，不能把队列登记等同迁移完成。飞书入口放在台账 `cloud.url`，不在多个文件维护不同地址。
