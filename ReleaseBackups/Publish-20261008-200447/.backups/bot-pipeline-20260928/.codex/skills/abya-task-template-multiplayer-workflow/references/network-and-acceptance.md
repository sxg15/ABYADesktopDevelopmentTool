# 联机协议与实际验收

## 状态契约

按玩法选择字段，不强制所有游戏包含关卡或分数。

| 范围 | 示例字段 | 归属 |
|---|---|---|
| 比赛 | matchId、phase、rulesVersion、contentVersion、participants、seed、deadline、results | 权威端 |
| 个人 | userId、ready、online、score、contentOrdinal、gameplayState、revision | 权威端判定，本人视图读取 |
| 输入 | matchId、对象/内容版本、source、sequence、action | 客户端提交，权威端校验 |
| 表现 | 朝向、动画进度、菜单状态、降低动态效果 | 本地，不能改变最终判定 |

身份来自认证会话，不能信任客户端任意填写的 userId。操作必须匹配归属、当前比赛、阶段与版本；丢弃过期或重复命令。异步完成回调也检查比赛/内容版本，避免旧动画完成后推进新对局。幂等计分，禁止重发成功消息反复加分。

若玩法规定动作不可中断或不可缓存，在输入层和权威层均验证忙碌状态。若禁止长按连发，记录按下/松开，忽略系统 repeat；切关或切阶段不清空仍按住的键来制造新按下。失焦时按设备事件能力处理输入，不让旧输入突然作用到新内容。

## 随机与时间公平

同题同序模式：由权威端产生比赛种子，使用明确版本的确定性 PRNG；内容由种子、稳定排序的题库、内容版本和个人题号决定。不能因玩家完成顺序、客户端帧数或其他玩家抽题消耗共享随机流而改变题目。明确抽样池、重复策略、洗牌袋和耗尽行为，检查题库大小不同仍能工作。共享场景模式按本身规则同步，不强行套用独立题号。

限时比赛使用权威截止时刻。客户端显示剩余时间，但不决定截止。规定以服务端接收还是权威事件时间判定边界；测试截止前后完成、网络延迟、同时完成与结算锁定。HUD 刷新节流不延后真实截止。

明确最低准备人数、开局名册是否冻结、迟到加入、断线、重连及主机退出。重连恢复同一身份，不能产生额外得分对象。再来一局更换比赛编号，清理个人状态、旧回调和旧命令，同时保留规则规定应保留的数据。

## 分层验证

1. 纯规则测试：典型输入、非法输入、边界、结果与验证器一致。关卡型游戏按项目要求批量校验种子与参考解，记录真实执行数量。
2. 协议测试：乱序/重复/旧比赛命令、对象归属、截止边界和幂等性。
3. 真实拓扑：托管 Host 加独立 Client，确认不同用户 ID、已联网和同一比赛。按目标人数补足客户端，不用同一窗口切身份冒充。
4. 完整对局：所有人准备、共同开始、各自操作、分数同步、规则规定的推进、时间结束或胜利、同分、再来一局。
5. 设备与故障：PC/手机布局、触控、失焦、重连、横竖屏切换；缺失内容时明确回退或阻止开局，不能卡住。

推荐记录表：

| 检查项 | 前置条件/输入 | 期望 | 实测及证据 | 通过/失败/未执行 |
|---|---|---|---|---|
| 身份隔离 | A 操作，B 不操作 | 仅 A 的个人状态变化，公共信息按规则同步 | 填运行断言 | 填状态 |
| 相同内容 | 同一种子、同一题号、不同完成时刻 | 公平策略要求的内容一致 | 填内容 ID/哈希 | 填状态 |
| 截止边界 | 截止前后提交有效操作 | 按明确规则计入或拒绝 | 填权威时间与得分 | 填状态 |
| 新版本 | 保存后启动独立实例 | 加载新的规则和题库版本 | 填读回与运行证据 | 填状态 |

真人难度、体验及网络质量不能仅由自动测试推断。自动操作测试完成后关闭脚本，留给用户的测试窗口应恢复可人工操作的准备状态。
