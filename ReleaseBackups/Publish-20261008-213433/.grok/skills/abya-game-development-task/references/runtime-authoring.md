# Runtime 预检、实现与验证

仅在需要检查、修改或运行玩法时读取。CLI 命令映射见 [cli-commands.md](cli-commands.md)。
完整流程写入前须确认需求和计划；局部任务沿用其明确范围及授权，不重复完整访谈。

## 托管实例预检

读取桌面 doctor、capabilities，确认任务上下文、存档和配置的 Player。
复用本任务适用实例；需启动时读取 [启动参数](game-launch-parameters.md)。
编辑检查用 editor，单机探测用 offline；联机用 lan-host 加独立 lan-client。
CreatorTest/Local 不作为联机证明。预检可管理临时实例，但对存档/玩法保持只读。
实例按默认 background 保持渲染，通过 CLI 截图和状态检查；人工检查或实际录像时按需显示窗口。
实时录像按 [录制指南](recording.md) 临时显示目标窗口，结束后恢复；这不改变默认后台运行方式。
等待进程及 Runtime CLI 就绪，慢启动/失败先读取启动报告，不猜测等待时间后认定成功。
新实例先 read_me_first，再按目标动态查询工具、Lua 文档和具体 API/schema。
同实例同版本已有有效查询可复用，重启、版本变化或不一致时重新核对。
检查存档/关卡、脏状态、资源和目标能力；无关用户内容不能因预检被保存、覆盖或丢弃。
可行性写为可直接实现、可实现但复杂、需要补充工具或当前阻塞，附真实依据和未证实项。

## 写入前与 Lua 实现

游戏内容变更读取 [架构约定](gameplay-architecture.md)，取得实际 snapshot，维护
artifacts/gameplay-architecture.v1.json，并提交完整 validate。错误阻止写入；
警告须修复或记录精确规则、目标、依据与例外。ready=true 后再实施。
Bot 新定义使用 [Bot 指南](bot-development.md) 的有限可撤销候选暂存例外；
先校验基础与候选 Lua，暂存后完整验证，再做其他绑定，不以省步骤跳过确定性错误。

新建或重写行为默认完整、自包含 ABYA-LUA String；按目标事件 scaffold，查询公开 API，
validate 后绑定。仅维护现有 APC、用户明确选择可视化，或确认原生 Lua/API 确实缺失时
采用最小 APC 范围，并记录原因。不得用 CS/反射、APC ID 调用器或假造 API 绕过限制。
运行时文档按本次实际修改需要读取；事件、数据、异步/执行侧规则发生关联时不可省略。

Global/Level 负责阶段、计时、生成调度和胜负；移动、武器、碰撞、生命及表现落在
对象/Prefab 或准确事件，优先原生投射物、碰撞与触发，不创建全局逐帧遍历实体的行为总管。
共享 FreeObject 行为按 prefab 目标 scaffold/validate，走 editor_prefab_logic_binding_*。
写前读绑定的 prefabRevision，提交 expectedRevision；核对广泛影响的授权和运行端检查。
无系统 Player 使用 generatePlayerMode=Manual；联网时对象按真实用户归属，分别验证
本地所有者、权威端和远端代理。不得由本地 UI 自行裁定权威结果。

导入、赋值、读回并实际查看计划采用的资源。生成/复制文件不等于已应用。
CustomUI 的文字对比、换行、父子范围、重叠/裁切、锚点和热区必须在实际状态与视口检查。
缺素材按计划阻塞处理，不默认扩展到生成全套素材。
每批采集相关截图、状态断言、日志、Lua/APC trace；有状态断言时不只凭图判断。
实现后 lint，修复错误，保留有依据的警告处置；结构修正后复验受影响行为。
保存任务修改、读回并由新实例重载验证版本，不把本地源文件更新当作运行版本已更新。

## 运行检查与恢复

单机证明目标就绪、核心循环、胜负、重开和清理；联网还须独立 Host/ClientOnly 的
不同身份、加入、归属、同步、退出和重开证据。目标人数超过双端时按需求补足验证。
有 Bot 修改时加载其专项指南和资料检查器，不把 Running/提交计数等同于动作被接受。
图像必须实际打开检查；桌面视口模拟不得写作手机真机测试。
范围、版本、运行状态、环境和目的相同的检查可共享，必要变化后再做对应复验。

实例无响应先尽力保留启动报告、日志、CLI 状态和截图，再停止本任务实例并核对退出。
每个实现阶段至多自动重启两次，持续失败保留依据并报告阻塞；不能停止别的任务实例。
停止可能丢失未保存状态，恢复前先判断待保留内容；不通过重载整个存档强行消除错误。
超时、取消或 outcome_unknown 先读实际操作与目标状态，再决定恢复，禁止盲目重发写入。
人工试玩前停止自动输入；最终区分静态、接口、真实运行、双端和用户认可的结论。
