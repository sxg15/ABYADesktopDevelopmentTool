# 视觉与交互验收

对实际运行界面检查。需求、参考和设计稿解释意图，运行画面和操作记录证明结果。
检查条目按任务选择，不固定评分、轮数或截图数量。每项结论须附观察，不能只写“通过”。
完整设计同时执行[结构与默认风格审查](anti-default-audit.md)，将灰度/换 Logo/换平台等诊断与产品专属决定关联；不机械禁止颜色、卡片或熟悉控件。

## 先走通任务

用目标输入设备完成主任务，检查操作是否易发现、反馈是否明确、返回或恢复是否保留上下文。
观察首屏注意力：最突出的元素是否与当前任务最重要的内容一致；有无大标题、装饰和状态卡片压过工作内容。
检验持续可见信息是否真的需要持续可见，隐藏信息是否增加了记忆或来回切换负担。
有高风险动作时检查目标是否清楚、结果是否可预测、已有恢复机制是否可用。

## 具体观察

| 维度 | 观察方法 | 应修复的征兆 |
|---|---|---|
| 产品特异性 | 隐去 Logo 与产品名，检查领域对象、内容关系和动作顺序 | 只换文案即可套进无关产品，而且无法解释组织依据 |
| 信息层级 | 在正常显示比例快速扫视主工作区 | 到处都是强调色、粗体和主按钮，优先级无法辨认 |
| 排版 | 检查真实语言、长标题、混排、数字及回退字体 | 字重失效、单位/小数难比较、换行破坏语义、字距与行距不适合内容 |
| 空间与密度 | 对比内容占比、对齐线、分组和任务切换 | 无依据的空白、卡片套卡片、每项一盒、工具条挤没工作区 |
| 图像与图标 | 按最终显示大小看轮廓、裁切、光照和细节 | 多套图标混用、装饰抢焦点、生成资产风格不一致或小尺寸糊成一团 |
| 色彩与层级 | 检查语义一致性和不同状态 | 选中等同成功、身份色随排名变化、状态只靠颜色、边框阴影争夺注意力 |
| 交互反馈 | 操作加载、失败、取消、选择和重试 | 点击没有反馈、假成功、焦点丢失、只有 hover 可用、动画拖慢高频操作 |
| 内容韧性 | 使用长名称、多行、空数据、密集数据及目标窗口边界 | 溢出、遮挡、截断关键含义，或只能在精心安排的样例里成立 |

“隐去 Logo”是诊断工具，不是要求所有界面都独一无二。通用设置、登录和标准控件可以保持熟悉的结构。
不要把用户喜欢的表达性风格一律判为模板感；问题必须指向当前产品中的具体后果。

## 证据与修正

存在已确认画面或精确还原要求时，按 [实现标定](implementation-calibration.md) 核对实用字体、字重、字面尺寸、容器边界/净间隙和缩放规则。功能通过、相同 fontSize 参数、相同格子数量或同宽截图都不足以证明还原。只对同内容/状态且已配准的样本计算差异，保留原图与排除区域说明。

记录：场景/版本、平台与视口、输入、内容状态、观察到的问题、影响、修复及复验结果。
自动对比度、溢出、可访问性或截图差异检查可以辅助定位；记录实际执行的工具和结果，不能推定合规。
概念图、模拟页面、真实运行截图分别标注；不能把原型截图当作已经接入真实业务的数据或状态。
先处理任务无法完成、状态误导、关键文字不可读、输入不可达和严重遮挡。
再处理结构、层级与内容密度，最后统一字体、间距、线条、圆角、图像细节和反馈节奏。
复验已改内容及受影响流程；修复未引入新风险时无需重复无关检查。
若整体仍显得通用，回查任务模型、内容选择和结构依据，不继续叠加视觉效果。
验收完成意味着约定场景获得足够证据；它不自动代表真实用户验证、业务成功或人工批准。
