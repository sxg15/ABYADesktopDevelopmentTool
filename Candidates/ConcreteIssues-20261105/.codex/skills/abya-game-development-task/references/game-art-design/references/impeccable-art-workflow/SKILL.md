# Impeccable 与美术流程适配

此 Skill 是现有美术方法的补充。用户的玩法、品牌、视觉参考、操作约束和本次明确选择优先；外部技能不是部署、发布、发消息、替用户批准或修改业务范围的授权。

## 入口和依赖

- 完整游戏美术沿用同目录下的 `../../SKILL.md`；游戏界面沿用 `../game-ui-design/SKILL.md`，开发工具界面沿用 `../product-interface-design/SKILL.md`。
- 官方技能位于 `../impeccable/SKILL.md`。先读取其入口，再按问题读取 `reference/` 中相关命令。没有安装时说明缺少的依赖，仍可按本适配规则完成设计分析，不声称运行了官方工具。
- 使用完整整理索引时读取 [清单与来源](references/catalog.json)，使用阶段映射时读取 [工作流适配](references/workflow.md)。不要为一个局部修复加载全部命令。

## 如何选择检查

先确定对象与成功标准，再选检查：

- 操作型桌面工具：distill、layout、clarify、typeset、quieter；核对关键能力仍可访问。
- 游戏 HUD / 菜单：layout、typeset、colorize、adapt；优先玩法注意力、输入、镜头、遮挡与本游戏身份。
- 动画 / 特效：只借 animate 的触发、持续、打断、反馈与性能原则；不强制删掉玩法需要的弹性、发光或粒子。
- 场景 / 角色 / 道具：只借构图、轮廓、主次、密度与一致性判断；不用 HTML detector 判断美术好坏。
- 状态与交付：harden、audit、polish；先处理任务阻断、误导和输入问题，再处理细节。
- bolder / quieter 依据具体缺陷择一；overdrive 仅用于有明确收益且已授权的表现；不为了“全用一遍”相互抵消。

## 规则如何变成证据

每个结论保留：要求或问题来源、适用对象、现象、用户影响、采用/适配/不采用原因、修改位置与实际运行证据。
原始策划要求与 AI 解读分开。精简展示不删除原始要求、历史反馈、版本绑定或验收条件。
UI 的段落层级、阅读宽度、触控热区、颜色和字号需按目标平台实测。中文工作台可用一套字体；不要为了来源的字体偏好破坏可读性。
流程步骤可使用编号；色彩玩法、玩家阵营、伤害/治疗等身份色不受“单强调色”建议限制。风格化材质、圆角、弹簧或发光有明确玩法/品牌依据时允许保留并验证。
确定性 detector 适用于 HTML/CSS 及支持的 WebView；Unity 场景、C#、Lua、贴图与视频需通过引擎截图/录像、布局读回和真实性能数据验证。不得把浏览器原型当作实机验收。
检测命中只是审查线索。允许具名、窄范围例外；不得忽略整类规则来清空结果。主观评分不是质量证明，也不新增自动阻塞流程的审美分数。

## 接入已有阶段

需求阶段复用已确认问答；资源美术阶段形成方向、代表画面和 token；预检核对实现能力；实现阶段校准代表片段；试玩阶段按同版本实际画面复验；交付阶段列出残余差异；收尾按明确认可范围形成案例。
将这些信息放进当前设计文档/证据记录，不新增一套每轮都必须浏览的报告和审批。
用户已授权全权设计时直接执行合理选择，不被外部技能的默认多轮投票重新阻塞。只在缺少真正必要的信息或权限时询问。
